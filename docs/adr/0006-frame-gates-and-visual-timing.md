# ADR-0006 · 帧门是整数分频，声明的帧率是预算不是愿望

状态：生效（首次记录 2026-10-07）

## 决定

舞台的帧门语义是「**每 N 个 rAF 给一帧**」，N 由实测刷新率换算且只往下取：
`N = max(1, ceil(实测 Hz / 目标 Hz))`。所以任何目标帧率只会兑现成 ≤ 它的值，
不会是别的数。档位表里写死的帧率必须是刷新率的公因数，否则声明就是在说谎。

刷新率来自 rAF 间隔的中位数 + EMA（吸收 59.94 / 119.88 这类假小数），最少样本数
不到就不换算 —— 宁可先用 60 兜底，也不要把启动期掉帧读成「这台机器是 30Hz」。

2026-10-08 复核：`gateRates().achieved` 是实测刷新率除以分频数得到的预算，不能标成已经执行的帧率。`HertzPerf` 在原有 `runGates` 边界计数与计时，实测速率取采样窗内计数差；不新增 rAF。验证必须走真实 `frame → schedule → frame`，直接调用 `runGates` 不能发现续帧时钟被清零的问题。主循环以局部 `frameDt` 采样，歌词门累积间隔不能污染刷新率估计；只有真正停机或隐藏恢复才清时钟基准。

2026-11-08 M0：Stage 预分配版本 1 借用帧，在同一个真实主帧采样一次并作为 gate 第二参数共享；第一参数和原整数分频不变。播放投影、anchor/discontinuity 分类与实际频谱收帧时间/revision 保留在 Stage，粒子 owner 持有实例 sceneTime、Onset、后端选择及生命周期。暂停/隐藏/遮挡/reduced/零尺寸/停绘冻结几何，恢复首帧 delta0，并等待恢复水位之后的新输入；静态补帧由 dirty 与原 kick 合并。涟漪的 WAAPI 始终暂停，时间和到期只消费同一 sceneTime，不保留墙钟 timeout。普通重锚不能当 seek 清输入，检测历史 reset 不能令公共拍序号倒退。renderer 消费显式帧与预算，不重读 Stage，不建立第二循环/registry。

M0 的创建、部分失败、真实非零预热和 context-loss 清理归各 renderer；先释放再回退，双失败显式 unavailable。HertzPerf 分开记录 attach、预热、生产首帧 CPU 提交及有效显示请求等待；API 字节和表面像素不冒充物理显存，诊断关闭不关闭原 A/B 保护。具体合同、资源口径、验证入口及 M1–M4 边界见[粒子帧合同](../stage-particles-frame-contract.md)。

## 禁止回退

2026-10-15 三维空间：按用户对 Mineradio 空间感的修订，舞台是首页的背景。
进入空间创建一个共享 Three.js renderer；首页与舞台切换只改变 UI 层，保留场景和镜头。
SpaceStagePure 不创建 rAF，Space3D 的 Stage 帧门统一推进音频信号、相机与场景。
歌词使用播放位置；几何动画使用随暂停/减弱动效冻结的 sceneTime，不能用音频位置驱动漂移。
暂停仅在参数、机位、歌词、封面或尺寸改变时合并补帧，隐藏态停止绘制。
退出整个空间才销毁宿主及资源 scope；丢失上下文显示失败状态，重试创建新宿主。
空间打开时二维视觉门通过 Stage 的覆盖状态停机，共享能量/音频时钟继续运行。
普通字幕为 DOM 叠加层，自带空间歌词的场景通过 ownsLyrics 能力收起普通字幕。

2026-11-01 二维局部流体：StageFluid 只登记一个 Stage 帧门，内部 solver 接受封顶的场景增量时间，
不持有 rAF、计时服务或音频分析器。暂停冻结，隐藏清空输入并停止绘制；关闭、still、减少动态及
三维／创意交接时释放自己的上下文。开关表达请求，实际不可用／保护暂停不回写请求偏好。
这项本机观看增强不增加二维录制来源，也不进入三维录制合成。
2026-10-15 歌词一致性修订：空间内四种 Stanza 演出复用原歌词时钟、主题、排版与特效，
由 space3d 帧门调用 frame，不新增循环。Pixi 初始化未完成时保留补帧，完成后恢复暂停休眠；
UI 门只同步配置，配置变化请求补帧。局部减少动态经歌词宿主传入共享渲染器，
隐藏页面时暂停 CSS 动画；沉浸模式保留歌词层。三维背景继续按自己的 sceneTime 推进。
画质帧率、DPR、几何与组合效果遵守同一宿主预算，压力降档不覆盖用户保存的画质选择。

歌词 renderer 的镜头、退场寿命与跨模式交接使用 `Stage.position()`，不能另用墙钟定时器
决定旧画面的存活。宿主 `stage3d` 在唯一帧门先绘制进场层，再推进两层透明度。
Pixi renderer 的 `isReady()` 表示已提交首帧或已有可见失败提示；初始化完成本身不等于
可以退掉旧层。等待期间保留旧画面。已开始的交接随暂停冻结，暂停时手动选择新模式则在
就绪时直接显示；离开歌词布局、关闭或销毁必须经统一可见性入口清理交接。

创意工坊直接编辑实际大舞台：`CreativeStage` 唯一持有预置、音频绑定和 cue；
`Stage3D.sceneSource` 持有呈现来源和挂载生命周期。侧栏增强偏好与大舞台开合独立，
同一时刻只绘制活动的创意目标，`creative` 帧门只在初始化登记一次。
秒级 cue 按 `Stage.position()` 求值，完成后保持目标，反向 seek 重新计算；
应用和系统的减弱动效必须冻结场景时间、镜头漂移与自动导演。

2026-10-11 构图边界：动画绘景（`presentation.family === 'anime'`）始终固定构图，
其它创意场景在高级编排打开期间也固定构图。`Workshop.isEditingAdvanced()` 只报告编辑状态；
`CreativeStage` 在既有解析/合成边界抑制镜头漂移、节拍冲击、悬停视差、松手惯性、
相机叠加层、自动导演/入画补间及镜头/整体缩放旋转的音频绑定贡献。
此策略不冻结场景时间，不改持久化预置；非镜头参数的音乐响应、手动机位与显式 cue 保留。
退出编辑后，普通三维场景恢复自动镜头。固定构图不能借用减弱动效开关实现。

创意场景自带三维歌词时，`Stage3D` 根据 `CreativeStage.ownsLyrics()` 的只读能力收起其它歌词层，
保留原歌词视觉偏好；全局歌词开关经创意宿主传给 GL 字形绘制。切回其它场景恢复原视觉，
隐藏的二维歌词不继续驱动动画。场景几何、材质及参数/机位静态定义归 `CreativeGL`，
`CreativeStage` 的导演、入画和复位消费同一场景描述，不新增帧循环或持久化字段。

`Backgrounds` 和 `HandDrawn` 各持有唯一可移动图层。创意舞台建立独立合成上下文，
自定义背景在底层，创意画布以 screen 混合在其上，歌词与漫画装饰在上层。
暂停参数变化使用合并补帧；歌词 DOM 更新后由宿主补画静态圈注，不能另开循环。

- 不许用 `round` 换算 N。帧率是预算，`round` 会让「60Hz 上要 48」兑现成 60 —— 多干
  25% 的活，且声明与实测都还好看，只有风扇知道。
- 不许在档位表里写除不尽的帧率（48/40/24 这一类在 60Hz 上都会兑现成别的数）。要改
  档位就同时改 `check-frame-gates.js` 的公因数断言。
- 帧门里 `fpsFn` 报 0 的含义全局唯一 = 停机，不是「不封顶」。参考实现的 `0` 是后者，
  照搬会把「收起」变成满帧空转。
- 估计器不许直接吃单帧尖峰：中位数在前、EMA 在后是刻意的两层。
- 不恢复独立模拟频谱预览，否则工坊与实际播放再次出现两套画面。
- 不把带不透明底色的自定义背景放到创意画布上方，否则场景和参数虽然更新，像素仍被遮住。
- 不以手绘帧门停机代替暂停时的歌词更新通知，否则 seek 或隐藏歌词会留下旧圈注。
- 不在每次 schedule 时重置 lastFrameAt，也不把 tickLyrics 改写的 lastDt 送给显示刷新率估计器。
