## 2026-11-05 进程模型更新：桌面歌词回到播放器进程内

独立形态（HertzStudio 播放器）**不再启动 `hertz-desktop.exe`**：`crates/hertz-desktop` 改为「库 + 独立 exe 薄壳」，播放器经 `crates/hertz-studio/src/desktop_host.rs` 在**本进程**调用 `hertz_desktop::start_embedded()`，直接创建歌词窗口。壁纸设置与原生预览挂载为主播放器窗口内的子视图；主界面、托盘和旧管理入口统一导航到该编辑区。命令走进程内 `mpsc` 进宿主的 tao 事件循环，复用同一个 `handle_pipe_request` 业务分派；命名管理管道只属于独立 exe（原生回归脚本仍直接 spawn 它），播放器侧不再有 `Command::new` 或 `management::request`，也不再有「启动 exe → sleep → 补发命令」。

启动、托盘与退出统一归播放器：

| 环节 | 唯一 owner |
| --- | --- |
| 启动 | `desktop_host::ensure_started`；冷启动如实回 `desktop_not_running`，UI 的 launch 入口在同一进程拉起宿主并直接开窗 |
| 托盘 | `--window` 时 `set_player_tray(true)`：宿主不建第二个图标、不抢占进程级菜单/托盘事件处理器；原宿主托盘动作并入播放器托盘 |
| 开机启动 | 注册表写播放器 exe（带 `--window` / `--data-dir`），播放器启动时按该偏好拉起进程内宿主 |
| 退出 | 原生托盘/页内/HTTP 退出先经过唯一确认与保存守卫，取消保留桌面宿主；批准后与 Ctrl-C 同走服务清理链中的 `desktop_host::shutdown()`，再释放房间/音频；见[主窗口生命周期](main-window-lifecycle.md) |

实现要点：内嵌事件循环用 `with_any_thread(true)` + `run_return`——tao 的 `run()` 在 Windows 收尾会 `process::exit`，会把整个播放器带走；独立 exe 仍用 `run()`。窗口类与消息窗口改为进程级单例、事件接收方随宿主换，宿主因此可反复启停。歌词/设置页资产、草稿、revision、来源域与配置提交逻辑逐字复用，已修改的歌词样式与设置功能、使用效果不变。

Windows 主窗口与桌面宿主的 Tao 循环统一为 `EventLoop<()>`，所有子窗口也使用 `EventLoopWindowTarget<()>`。Tao 0.37.1 按进程注册窗口类，类回调却绑定事件泛型；两个循环使用不同 `UserEvent` 时，后建窗口会进入先注册的回调，导致事件数据误读和崩溃。`native_events.rs` 将各循环的业务事件保留在独立的类型化 `mpsc` 队列中，Tao 只发送 unit 唤醒；发送与取出由同一短锁保证顺序，一次唤醒消费一个事件，原生唤醒失败时返回原事件。非业务窗口事件通过 `map_nonuser_event` 原样转交，保留 DPI 等借用事件的生命周期。

**DBX 插件形态不受此改动影响**：插件侧车没有原生窗口，仍按[桌面组件分发](./desktop-component-install.md)使用可选安装的组件及其管理 v2 协议；下文该形态的既有结论继续有效。

静态契约：`node scripts/check-desktop-in-process.js`（已接入 `check-frontend.js`）。

### 主程序内联歌词设置

独立播放器的歌词设置使用已有 `POST /v1/desktop/control`。以下窄命令按需初始化进程内宿主，不打开设置中心、不调用定位；已保存 `enabled=false` 的歌词保持关闭。业务结果返回 HTTP 200 的 `{ok, revision, lyricsConfig, pendingSave, canLock, positionEditing, positionOwned, positionLeaseMs, runtime}`；失败另含 `error` 与 `message`，并带当前快照，前端保留自己的草稿。宿主初始化等基础设施失败仍返回既有 HTTP 错误信封。首个命令允许 55 秒等待，覆盖 30 秒初始化与 20 秒命令期限。

| command | value | 行为 |
| --- | --- | --- |
| `lyrics-settings` | 可选 `{owner}` | 读取完整歌词配置、revision 与实际显示/锁定状态；匹配的位置会话续约 |
| `lyrics-apply` | `{expectedRevision, lyrics}` | `lyrics` 为从快照复制的完整配置；仅提交歌词并增加 revision |
| `lyrics-position-begin` | `{expectedRevision, owner}` | 临时显示并解锁歌词，以便拖动；同 owner 重复调用只续约 |
| `lyrics-position-done` | `{owner}` | 只保存 `anchorX`、`anchorY`、`monitor`，恢复原启用、锁定与隐藏状态 |
| `lyrics-position-cancel` | `{owner}` | 恢复调整前设置与位置，不增加 revision |

歌词提交拒绝旧 revision、尚未落盘的样式条修改和活动位置编辑。落盘成功后同步原生锁定、歌词页面、窗口位置与可见性、小窗已唱色和托盘，再通知原生设置中心；壁纸配置、显示组、预览和原生中心草稿均不重建或清空，旧草稿按 revision 正常冲突。用户从停用切换为启用时清除运行期隐藏标记；全屏、会话、显示器和无内容等策略仍按实际状态决定可见性。常见错误码为 `revision_conflict`、`position_edit_active`、`invalid_value`、`tray_unavailable`、`save_failed`、`config_busy`。

位置调整的 `owner` 由页面生成随机 UUID，不回显其他页面的 owner。租约为 120 秒，拥有者在调整期间每 10 秒读取一次 `lyrics-settings` 续约；页面离开时应取消，租约到期也自动恢复原设置。快照的 `lyricsConfig` 在调整期间始终是原保存配置，`runtime` 表达临时显示/解锁状态。其他页面和原生设置中心不能完成或取消这一会话；错误码为 `position_owner_mismatch` 或 `position_edit_inactive`。这些新命令只从内嵌 HostAction 入口分派，不扩展 DBX 授权或命名管道管理协议。

单实例按当前 Windows 用户身份约束，并校验交互会话。首版只支持同一用户的一处有效桌面宿主；第二次启动将请求交给既有兼容宿主。同一用户另一会话存在宿主时报告会话冲突，不跨会话抢占、终止或创建竞争配置写者。会话断开时原宿主停止呈现。命名对象的 ACL、会话辨识与重新进入行为由原生验证证明。

共享进程崩溃可能同时影响两个 surface，这是共用宿主的明确代价；单个 controller 失败只使对应功能失败。托盘、配置与来源不各建一套。

## 2. 播放生命周期的当前事实

当前 `AppState::schedule_depart_pause` / `pause_if_alone` 在最后播放器页面离场后等待 `DEPART_GRACE`（现为 3 秒），复核观众、房间与实际原生 owner。普通浏览器/DBX 没有原生主窗口 owner 时仍使未完成播放意图失效并暂停；2026-11-06 `--window` 增量使用真实主窗口 RAII owner 保持后台播放，页面重载或 WebSocket 断开不再误停，见[后台播放与睡眠定时](native-background-sleep.md)。没有新增假观众或全局永久保活开关。

桌面 feed 不计入播放器观众，也不连接主 `/ws` 来维持观众数。没有原生主窗口 owner 时，关闭最后播放器页面仍按原策略暂停，歌词按暂停位置冻结，壁纸继续无音乐的环境动画。仅保留歌词/壁纸组件不能保活音乐；有效原生主窗口 owner 才提供新增后台行为。

原生 owner 退出时永久关闭本地输出许可并进入既有服务关闭流程；睡眠定时由服务和音频门控协作，独立于页面。不得靠虚构观众、伪造 `playing` 或新增桌面播放器改变普通运行方式的行为。

## 3. 来源身份与切换

区分三种身份：持久的服务 profile 身份、每次服务启动的 session、宿主当前绑定的内存代际。profile 以发行版与规范 DataDir 对应的服务身份确认；端口、PID、程序文件名不能替代来源身份。宿主绑定代际只用于作废旧来源异步工作，不替代音频 actor 的播放 generation。

现有 `vmusicd.json` 已补充 `edition`、`data_dir`、`server_instance_id` 与歌词/壁纸只读协议字段；宿主用这些字段核对来源，钥匙仍只由原生层读取。宿主在发现记录缺失或身份不符时停止音乐桥，不从端口扫描或另一发行版自动补齐。

来源切换作为一次显式配置提交，按以下顺序完成：

1. 展示当前与目标发行版/profile，并说明同时影响已启用的歌词和壁纸音乐响应；请求携带预期配置 revision。
2. 校验目标引用和配置。服务不在线时允许保存为等待来源，但不得宣称已认证连接。未知来源不从端口扫描或另一发行版自动补齐。
3. 宿主串行提交 activeProfile，递增配置 revision 和绑定代际；清空旧歌词、播放锚、频谱与待处理消息，取消旧观察。
4. 按目标 profile 自己保存的 enabled 与样式启动功能。若用户同时明确要求启用某项功能，在同一次配置提交中设置该项；不复制另一 profile 的启用状态或参数。
5. 用目标 DataDir 的发现记录与对应窄凭据连接，认证快照再确认发行版/profile/session。旧代际结果全部丢弃；连接失败保留新绑定的等待/失败事实，不静默切回旧源。

两个 surface 始终使用同一 activeProfile；歌词停用时壁纸仍可有来源，壁纸停用时歌词独立可用。断连、切换和重新启用均须覆盖原请求迟到的反例。

## 4. 配置提交与实际运行分离

宿主唯一配置位于 `%LOCALAPPDATA%/Hertz/Desktop/config.json`。当前配置包含 `schemaVersion`、单调递增 revision、`launchAtLogin`、`recoveryHotkey`、activeProfile 和各 profile 的独立 lyrics/wallpaper 域；合计最多 64 KiB、8 个 profile。**可选恢复快捷键按本节实现为全局 `recoveryHotkey` 字段**：默认空（未设置时编码省略该字段，旧宿主仍可读），只在宿主全局保存一份，不随 profile 切换，也不在歌词/壁纸或播放器另存副本。凭据、完整音频 URL、运行期暂停原因与歌词正文不写入配置。当前实现为 schema v3，将 v1/v2 旧来源迁为 `standalone`，DBX 来源显式携带插件身份；v1 无活动来源的旧偏好保存在 `unboundStandalone`，仅首次显式绑定独立版时消费。迁移通过原子提交增加一次 revision，失败不覆盖原文件；完整来源合同见 DBX 方案第 4 节。

达到 profile/容量上限时拒绝新增并提示用户整理，不自动丢弃当前来源或已保存配置。只实现有明确旧版本输入与回退证据的迁移，不用默认值覆盖未识别字段后宣称兼容。

持久配置表达用户意图；实际窗口、来源连接和系统自启项是可单独查询的运行事实。逻辑状态投影如下，字段编码在进入 L1/W1 前冻结：

| 状态层 | 必须能表达的事实 |
| --- | --- |
| 配置 | 当前 revision、activeProfile、两项 enabled、全局自启偏好 |
| 来源 | 未绑定、等待服务、已认证连接、身份/协议不符；当前 session |
| 各 surface | 关闭、启动中、运行、因策略暂停/隐藏、等待环境、失败；目标 revision 与实际应用 revision |
| 自启项 | 期望开关、检测到的实际状态、更新失败原因 |

变更经过原生字段与对应 surface 校验，只有一个配置写者；原子替换成功后 revision 才递增。内存配置不先于持久提交宣布成功，旧 expectedRevision 返回冲突和当前 revision，调用方读取后重新编辑。配置写入失败保持旧配置，并明确本次未保存。

配置提交成功后才尝试应用窗口/场景；应用可能耗时或失败。成功答复须区分“配置已保存”和“窗口/场景已就绪”，运行完成按目标 revision 回报。旧异步完成不得标记新配置为已应用。**设计目标**是应用失败保留已提交意图与错误，用户可明确重试或改回旧配置；不把配置和 Windows/GPU 操作宣称为原子事务。

**当前例外与待修复项：**`crates/hertz-desktop/src/app.rs:1159–1164` 的挂载失败分支仍回写旧配置，因此不能宣称所有分支均已满足保存/运行分离。修复验收须在成功保存新 revision 后注入挂载失败，证明新意图和 revision 保留、运行失败单独可查、旧异步结果不能覆盖；重试使用已保存意图，改回旧值必须显式提交。另测落盘失败仍保持旧配置，不能把两类失败混为“应用失败”。

退出某一功能优先让其安全停下，并尝试持久设置 enabled=false。落盘失败时仍停止本次运行，提示退出偏好未保存、再次启动可能恢复；不能把临时停止报告成永久关闭。两项均停用且设置关闭时退出进程。坏配置保留诊断副本并停用，未来 schema 拒绝改写；修复/迁移不能未经说明启用另一项功能。

2026-11-08 独立退出修复已进入新候选验证：`lyrics-exit` 与 `wallpaper-exit` 各停止自己的功能；`quit` 保留整个桌面组件关闭语义，托盘文案明确区分。回复分别报告 `runtimeStopped`、`saved` 和 `persistenceError`；查询的 `runtimeEnabled`、`sessionStopped`、`exitPreferenceSaved` 与持久 `enabled` 分开。内联歌词快照的 `runtime.enabled` 表示本次实际启用状态，`lyricsConfig.enabled` 保持持久偏好。歌词/壁纸的迟到 HTTP 消息沿各自 stop token 拒绝，DBX 继续使用原 targetProfile/requestId/buildId 准入；两项停用后设置或 Mini 仍持有宿主时保留，自动退出消费事件时重新检查持有者。原生及配套生产端验收状态见[修复工作记录](aegis/work/2026-11-08-desktop-feature-exit/20-checkpoint.md)。

## 5. 管理协议与恢复

管理面为当前用户受限的本机命名管道；拒绝远程连接，验证用户与会话。播放器经已有鉴权服务调用窄管理门面，托盘和内嵌设置调用同一宿主处理入口。原生页面消息仅来自组件内嵌可信 origin，按字段校验；不接收任意路径执行、shell、脚本或窗口句柄操作。

逻辑请求包含协议版本、requestId、命令、目标 surface/profile、预期 revision（配置变更必需）和有界 payload。回复关联 requestId，并返回当前 revision、配置是否提交、运行状态及结构化错误。初始命令语义为：

| 命令类别 | 要求 |
| --- | --- |
| 查询、打开设置、解锁并定位 | 不改变播放；解锁以原生实际穿透状态为准 |
| 校验/预览、提交配置、显式切换来源 | 预览不写配置；提交检查 revision；来源切换遵守第 3 节 |
| 暂停/继续、显示/隐藏、停止指定功能 | 使用明确目标状态，不用 toggle；停止与临时暂停语义分开 |
| 设置自启 | 同时报告配置意图和操作系统实际结果 |

requestId 用于关联回复，不单独承诺跨进程的执行去重。请求超时或管道断开时，调用方先查询当前 revision 与状态；配置重试带原 expectedRevision，已提交的旧请求会冲突，不再执行一次。临时动作设置确定目标值；不因回复丢失循环创建窗口。设置查询失败时显示“结果待确认”，不能声称操作已完成。

所有连接、输入帧、等待命令、输出缓冲和执行期限都必须有界；配置提交串行，慢客户端不能占住托盘/退出所需的消息循环。具体 framing、包体上限、连接/排队上限和读写期限在原生实验报告中给出候选数值，经满载/慢读/半帧/断线试验后冻结，进入生产实现前必须完整，不能以本逻辑契约代替 wire schema。

设置预览沿用单一租约：最多一个预览、最长 15 秒、每 5 秒续租，关闭立即回收；新租约必须等旧预览资源释放后生效。壁纸预览最多 15 fps；歌词预览不增加 WebGL renderer。切来源、退出设置或不兼容版本使租约失效，不能留下无人管理的预览进程。

### 5.1 已有恢复入口与全局恢复键

托盘、播放器入口和中心的解锁/定位已实现，继续作为独立恢复路径；全局快捷键于 2026-11-05 按本节事务交付（隔离原生宿主验证覆盖注册占用、注入按键端到端、替换/释放、重启持久与启动冲突），不展示无效键位，也不降低[歌词 U3](./desktop-lyrics.md#11-验收与证据)的托盘独立验收要求。

可选全局“解锁并定位歌词”键默认空。唯一宿主使用 `RegisterHotKey` 注册，在消息循环消费 `WM_HOTKEY` 并复用已有恢复命令；不安装键盘/鼠标钩子，不抢占系统保留键。注册实际状态和已保存偏好分别查询，不用配置值冒充已生效。

更换按串行事务执行：校验组合键和 expectedRevision → 保留旧注册并试注册新键 → 带 revision 原子保存新偏好 → 注销旧键。同键不重复注册；清空偏好先保存空值再注销旧键。冲突或保存失败时注销候选、保留/恢复旧注册与旧偏好，明确未更换；若旧键注销失败，撤销候选并恢复旧状态，已保存的新偏好须以新 revision 补偿，不能倒退 revision 或掩盖补偿失败。失败时报告实际注册状态，避免两个恢复键被误报为单一成功结果。

启动时仅注册非空偏好，失败保留用户选择并反馈真实原因，仍可用托盘修改/清空；不自动换组合键。正常退出注销全部本宿主注册。验收覆盖默认空、冲突、成功替换、落盘失败恢复、注销/补偿失败、启动失败和退出释放。全局键只发恢复意图，不绕过锁屏、安全桌面、会话或全屏限制；这些原因解除后再按原规则定位。

## 6. 数据权限和版本边界

歌词与壁纸分别使用 `desktop-lyrics-key`、`wallpaper-key`；权限不互通，也不继承管理面、主 WS、主播放器 API、曲库或 AI 权限。2026-10-28 歌词原型落地后，歌词凭据除两条只读 GET 外，仅增加 `POST /v1/desktop-lyrics/control`：显式播放/暂停与当前文档句首 seek，校验来源、歌曲和代际，最终提交复用原播放 owner；壁纸仍只读。服务负责在用户明确启用时创建/管理窄凭据，宿主原生层读取；页面仅收到无凭据的校验数据。仅有本地文件权限的同用户恶意进程不在这层隔离的防御承诺内。

进入 L1-A/W1-A 前需将以下契约与服务实现一起冻结：

| 契约 | 必须确定并验证的结果 |
| --- | --- |
| discovery 与 profile | 来源身份的稳定/会话语义、原子发布与有界读取、路径规范化、旧文件兼容；修改原发现记录不破坏现有使用者 |
| 窄凭据生命周期 | 创建、文件/父目录权限、失败清理、轮换/删除后的旧连接失效与重连；不接触另一 DataDir 或扩大 OBS key |
| 管理 IPC | 完整请求/响应 schema、大小/并发/期限、错误码、revision 冲突、丢回复后的查询恢复 |
| 歌词数据 | snapshot/document 的字段与范围，documentKey 失效，seq/generation 编码，偏移一次应用及非重叠读取 |
| 壁纸数据 | snapshot/events 首帧与重连、64 槽频谱范围、新鲜度、慢消费者合并与取消 |

2026-10-24 W1-A 冻结：壁纸先采用 `wallpaper-key` + `GET /v1/wallpaper/snapshot` 快照轮询，`/v1/wallpaper/events` WS 延后到 W1-B；字段、错误码与暂停/断连/频谱衰减语义见[壁纸只读桥](./desktop-wallpaper.md#w1-a-冻结首版只做快照轮询2026-10-24)。

服务、组件与内嵌资源按同提交生成可识别的 build identity；组件自身只加载随包匹配的页面与脚本。服务与组件通过各自协议握手，不把“软件版本相同”当作资源完整性验证。

管理协议不兼容时拒绝新配置命令；数据协议不兼容时停用对应来源数据，歌词清空、壁纸可保留已有环境动画。已有兼容宿主不能被第二份 exe 静默覆盖；不兼容启动显示升级需求，原宿主仍提供退出。将来允许跨提交兼容时，必须明确协议范围和回归矩阵。

## 7. 分发、自启与待实测决定

首版 Windows 11 x64 独立形态；Standard/Full 共用桌面组件实现，源服务仍控制来源能力。基础播放器不依赖组件。DBX 的只读数据桥、授权、来源迁移、原生管理 v2 与共用门面/设置入口已按[专项方案](./desktop-dbx.md)通过分阶段审查；组件由用户独立启动，未授权启动不探测组件。完整 D3 发布验收仍待完成，不据此宣称 DBX 已正式交付。其他 OS/ARM64、后台播放新策略另行设计。

推荐初版为用户显式获取的匹配组件包，与独立播放器同安装目录，服务只定位该固定相邻组件；不自动下载/解包。安装/升级应先正常关闭旧宿主，校验配套版本后切换，失败时保留原可恢复包与配置。具体 zip/安装器布局、文件清单、版本握手和自启路径必须在 L1-C/W1-C 候选前绑定产物，不以开发目录验证替代。

全局 launchAtLogin 默认关闭，仅建立一个当前用户入口，不创建系统服务或管理员任务；启动路径不带长期凭据，恢复 activeProfile 中 enabled 的功能。两项都停用时不启动空宿主；移动便携目录时由用户触发路径修复。配置提交与系统启动项更新分别报告；卸载只清除本组件入口，用户配置去留明确选择。

WebView2 Evergreen 依赖检测失败时显示安装指引，不自动安装；环境、用户数据目录与普通浏览器/DBX 隔离。最终关闭需释放全部 controller/environment 并核实专属进程退出；没有可靠进程归属证据时不按进程名批量结束 WebView2。

L0/W0 已有分项实验，Rust 绑定及 MSRV/许可、透明与后台合成、进程归属、跨会话行为和 CPU/GPU/内存阈值仍须按具体记录核对覆盖范围。未覆盖项继续补证，不将全部原生能力重新标成未实现；L1-C/W1-C 前绑定候选版本、支持证据及采用/调整/停止结论。后续实际变更再按需更新 ADR-0006/0009，不能把未冻结数值记成现行约束。
