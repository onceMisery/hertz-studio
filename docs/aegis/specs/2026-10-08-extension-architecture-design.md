# 扩展入口收敛

## 批准范围

用户要求按本聊天的架构评估改善皮肤、舞台、音乐渠道及资源扩展，采用工作树，不用 TDD。实施在 `codex/extension-architecture`，基线为 `ae26155`；原目录不修改。先实现，再补具有行为意义的回归用例并运行现有检查。

## 设计与取舍

采用内置注册表与明确生命周期。与仅拆大文件相比，此方案消除重复登记；与动态插件平台相比，它保留零前端构建、单 exe 和 DBX 的现有分发。此轮不新增产品功能，不调整视觉参数和播放授权，不引入依赖注入容器或第三方插件装载器。

- 场景：创意场景描述统一持有参数规格、默认值、机位、提示词别名及是否自带歌词，GL 和编排消费同一份定义。沉浸场景绑定构造工厂；歌词 renderer 用描述与实例表收敛宿主分发。保留各自绘制技术。
- 皮肤：Skins 统一执行旧皮肤卸载、新皮肤挂载和事件广播。复杂皮肤登记现有生命周期，业务动作改用通用的皮肤宿主协议；去除依赖事件监听顺序的挂卸载与专属桥接分支。
- 音源：平台描述与可调用实现登记在同一个 Provider 入口，按实际能力分组；公共 API 持续负责校验、能力门与超时。迁移现有平台，不改上游协议。测试调用真实注册项，退役复制分发名单的测试。
- 资源：一个显式内嵌资源清单同时生成路由与缓存指纹输入；HTML 仍声明加载顺序，DBX 继续直接打包 UI 目录。禁止新增资源后还要分别改多份 Rust 清单。

## 不变量与归属

保留皮肤/场景/音源 ID、localStorage 与服务端设置键、分享格式 v1、公开 HTTP/RPC 信封。Stage 独占动画帧时钟；CreativeStage 独占预置、cue 和音频绑定，场景描述只持有静态定义；AppState 与既有 app 动作仍拥有播放意图。注册错误应在登记边界可见，不能靠重复默认表掩盖缺失。

## 验收

虚拟扩展能经真实注册接口接入，错误注册可被拒绝；复杂皮肤往返切换先卸载后挂载且恢复业务节点；已保存场景预置归一化等价；能力与实际函数绑定一致；资源清单能驱动全部现有路由与指纹。现有前端聚合检查、Rust 测试与构建通过，并用真实浏览器检查关键皮肤与舞台切换。
