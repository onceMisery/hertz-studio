# 歌曲聚合搜索、加载与展示优化

状态：用户已确认，已实施。实现与验证记录见 `docs/research/aggregate-search-experience.md`。

## 目标与证据

让用户更快看到相关歌曲，能继续查找并明确理解每个音源和歌曲的加载状态。

当前实现证据：
- `crates/vmusicd/web/online.js` 的 `searchAll` 等待聚合响应后一次性清空并绘制列表，每源请求 20 首，没有分页入口。
- `crates/vmusicd/src/online/aggregate.rs` 并发搜索，但 `collect` 等待所有任务后返回；`online/mod.rs` 为每源设置 6 秒预算。
- `searchOnline` 和 `searchAll` 未按请求代际判断响应是否仍有效，旧请求可能覆盖新的搜索。
- 结果按音源固定分组，没有跨源相关性排序；计数展示上游总数，未区分实际已加载数量。
- `playAll` 只给底部播放按钮加载样式，歌曲行缺少加载反馈。

参考依据：
- Folia `src/stores/useSearchNavigationStore.ts`：请求编号、分页、按关键词与来源保存结果和滚动位置。
- Folia `src/components/app/search/SearchWorkspace.tsx`、`SearchResultRow.tsx`：独立初次加载/加载更多状态、重试、歌曲可用性、缩略封面和歌曲信息层次。
- VCPChat `Musicmodules/music-player.js`：切歌时立即更新请求编号、作废旧歌词，异步返回后检查当前意图。
- VCPChat 的多源歌词候选机制属于歌词场景，不能直接当作歌曲聚合搜索实现照搬。

## 方案比较

1. 仅修复竞态并优化现有分组样式：改动小，但首屏等待和可搜索深度不变。
2. 渐进聚合与独立分页，配合相关性排序和加载反馈（推荐）：复用现有单源 API 和 Rust provider；前端统一管理一次搜索，各源独立返回、重试和翻页。
3. 新增服务端流式搜索协议与跨源歌曲实体：扩展空间更大，但增加协议、实体合并和兼容成本，当前无必要。

## 推荐设计

### 搜索

- 依据服务端音源能力与可用性清单并发调用现有单源搜索接口，各源完成后立即展示；单源失败不阻塞其他结果。
- 搜索、切换来源、清空关键词均使旧请求失效。支持取消时中止旧请求；无论取消是否成功，响应都必须检查代际。
- 每源独立维护 offset、加载状态、错误和是否可继续；页游标按上游返回数量推进，去重后数量不能用于推进游标。
- 以 source + id 消除同源翻页重复；不同平台、Live、翻唱、伴奏等版本保持独立，避免误合并。
- 提供综合结果和来源筛选；综合结果按歌曲名、歌手、专辑匹配度排序，同分顺序稳定。匹配评分只使用已有元数据，不伪称语义搜索。
- 提供按源重试和继续加载，空页/重复页需终止无效翻页；总数不可靠时不凭总数承诺一定有下一页。
- 会话内有限缓存按查询与来源存储，明确容量和时效；登录/账号变化后失效，避免缓存过期权限状态。

### 加载与播放

- 区分初次搜索、某源仍在搜索、追加结果、歌曲正在加载与加载失败。
- 点击歌曲后在该行展示状态，重复点击同一待加载曲目不产生重复请求。
- 审查前端播放返回与后端既有加载代际的一致性；仅最新播放意图可更新界面，失败保留真实错误与可重试入口。
- 复用现有音频缓存、渐进下载、虚拟歌曲 ID 和播放器状态。是否需要调整音频下载链路，以实现阶段定位和测试证据为准，不先假定下载器有性能问题。

### 展示

- 搜索头部显示关键词、已加载歌曲数与音源完成进度，来源按钮提供筛选及状态。
- 结果行保留封面、歌名、歌手、专辑、平台、时长和 VIP 标识，增加匹配高亮与清晰的加载/失败状态。
- 首次加载使用骨架占位；追加时保留现有内容和滚动位置；封面失败使用稳定占位。
- 继续使用当前皮肤变量、官方平台图标和现有收藏/加入歌单操作，兼顾窄屏、键盘操作与减少动画偏好。

## 边界与所有权

现有 Rust provider 继续负责账号、平台协议、权限和曲目归一化；前端搜索状态负责聚合展示，不另建平台适配层。现有 `/v1/online/search/all` 保持兼容，不因页面迁移直接删除。聚合单曲播放沿用已有行为，不扩展为跨源整盘队列。

保留工作区已有未提交修改，尤其 `online.js`、`online.css`、`app.js` 和皮肤相关文件；两个参考仓库仅作只读参考。暂不新增平台、不绕过会员权限、不扩展歌词舞台或推荐系统。

## 验收

- 模拟一个快源和一个慢源：快源结果在慢源结束前可见。
- 连续搜索、切源、清空、旧请求晚返回，不能覆盖当前结果和加载状态。
- 每源分页、重复页、空页、失败重试不丢数据、不重复添加、不无限请求。
- 相关性排序和版本保留有可重复验证的样例。
- 点击歌曲可见行内加载反馈，失败可恢复；旧播放响应不覆盖新意图。
- 现有在线搜索、歌单、收藏与资源检查通过；必要的 Rust 测试按实际改动运行。
- 浏览器验证桌面/窄屏结果、骨架、部分失败与分页；真实平台接口失败与代码测试结果分别记录。

## 实施顺序

先补搜索竞态和分页回归测试，再实现搜索协调状态；随后完成相关性和界面展示，最后处理播放反馈并做集成验证。架构复核重点是搜索状态唯一所有者、现有 API 兼容、缓存失效与播放意图一致性。
