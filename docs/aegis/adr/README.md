# 决策日志（ADR）

这里记的是**带数字的决定**，不是「我们为什么选 X」的随笔。每篇固定三段：

- `## 决定` —— 选了什么、为什么不选另一个；一段话讲完。
- `## 边界与 owner` —— 表格。每行四列：`名称（含单位） | 数值 | \`文件路径::常量名\` | 改它要一起改什么`。
  数值列只写纯数字（`20000`，不是 `20_000` 也不是「两万」），单位写在名称里。
- `## 禁止回退` —— 一条条列出来，每条都要说清「改回去之后失败长什么样」。只写
  「不要这样写」的清单没有价值，能复现的失败形态才有。

## 为什么值得被脚本引用

`node scripts/check-adrs.js` 会把「边界与 owner」表里每一行的数值与源码里那个常量的
字面量对一遍。数字被改了而文档没跟上（或反过来）就是红。这样决策日志才不是会腐烂的
注释，而是**当前实现的目录**：想知道某个限制是谁、在哪儿、为什么是这个数，先来这里，
再点进源码。

新增一条边界时就加一行；改名或删常量要同时改这里，否则 CI 报的是找不到常量。
