# 架构对齐与交付边界

本轮采用工作树并遵照“不用 TDD”：先改造，再补真实注册、失败清理与跨模块往返回归。保留内置扩展模式与现有产品表现，没有引入第三方插件装载器或新依赖。

## 架构对齐

结果：aligned。核对 README、ADR-0001/0006/0007/0008 及批准设计，播放意图仍由 app/AppState 持有，Stage 仍拥有唯一时钟，CreativeStage 仍拥有预置/cue/绑定。Provider、皮肤 registry、场景定义和资源清单分别拥有其静态声明与接线，不再复制平台/场景/资源事实表。

ADR 回填：新建 ADR-0009，修订 ADR-0006 的场景能力与静态机位归属说明；原数值预算、ID、保存键、分享 v1 和 HTTP/RPC 信封保留。注册验证与分享验证共用原参数幅度边界，避免接受不能往返的扩展。

## 修复与退役

- 修复：部分皮肤挂载、失败恢复和 renderer 初始化的资源清理；机位/分享数值边界；特殊提示词别名；凭据回归的全局单例竞态。
- 退役：逐操作 source 分发表、独立 JS/CSS 路由/指纹表、皮肤专属动作事件、场景参数/机位重复表、单独 builder 表及 renderer 多份名单。
- 保留：派生 SOURCES 兼容视图、已有公共方法、HTML 加载顺序、图片响应、平台专用交互和 starborn 选镜算法。以后新增公共业务能力仍需宿主实现；登记表不替代业务代码。
