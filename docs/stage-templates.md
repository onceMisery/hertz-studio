# 创作模板候选

工坊→高级编排→场景新增三个本地模板候选。它们复用原场景、规范默认基线、完整预置校验器、临时预览 owner 与分享 codec，不调用模型、不创建任务、不读取歌曲或歌词。模板尚待独立人工视觉验收，不能按正式创作模板已验收计入路线完成。

| 模板 v1 | 场景与氛围 | 运动与边界 |
| --- | --- | --- |
| 静夜星球 | orb；克制、留白，低泛光 | 低漂移、无节拍抖动；球体仍响应实际频谱，不能称为完全静止 |
| 霓虹律动 | towers；明亮、清晰 | 中等频谱响应与缓慢漂移；低配置设备可触发既有分辨率降级 |
| 墨线地形 | terrain；单色、纸感 | 缓慢地形移动、无节拍抖动；后处理与横竖屏构图需要分别检查 |

来源为 Hertz Studio 内置配方，目录保存在 `plugin/ui/creative-templates.js`。每个配方固定模板 ID/版本、舞台契约版本/hash、目标场景默认基线 hash；不会在读取时用当前 hash 给旧模板补签。版本不一致时按钮禁用，直接调用准备入口也拒绝；后续改变配方需显式更新版本与验收记录。

点击「预览」后先校验固定信封，再从目标场景默认值创建完整候选，补入模板名称，验证完整预置和分享往返。临时预览身份同时绑定模板 ID/版本、草稿信封与完整具名候选，不只绑定一张卡片或一个名称。确认应用前再准备一次并核对身份及原预览 revision；普通编辑、取消、切页、关闭或页面隐藏会使候选失效，迟到的准备结果不能回填。

应用会替换整份当前预置，清除旧 cue/绑定/工程上下文并采用模板自身默认基线；模板的自动导演默认关闭，场景内的实时频谱响应仍存在。操作不会播放、切曲或主动读取媒体。要保留当前作品，先保存工程或另存收藏。模板只是一份新作品的起点，应用后可继续修改参数、手动分段、保存工程、分享与导出。

## 动作说明与版本范围

| 入口 | 行为 |
| --- | --- |
| 模板候选 | 从明确默认基线创建，临时预览，显式应用后替换当前预置；不自动收藏 |
| 意图草稿 / AI 提案 | 带版本的待确认候选，复用相同预览与应用 owner；AI 提案另需服务端状态复查 |
| 当前编排 | 已提交的完整预置，本机自动保存，参数/cue 编辑立即影响它 |
| 存进工坊 | 另存完整本机收藏快照；载入收藏立即替换当前预置 |
| 分享码 | 携带完整 preset v1；载入即应用，媒体内容身份与工程时间线契约由工程文件承载 |
| 工程文件 | 携带工程/时间线/场景契约版本、完整预置与可选本地媒体身份，检查后显式应用与媒体确认 |
| 视频 | 当前呈现的成片，不是可编辑工程 |

卡片展示内置来源、模板版本、兼容状态及适用边界；详情提供契约与默认基线 hash。当前预置显示实际 preset/工程版本，本机收藏只展示已有事实。普通 preset/分享/收藏格式不保存可信模板来源；应用、修改后不会把名称相同当作来自某模板，旧收藏缺失的来源与契约信息保持未知。hash 表示版本/内容一致性，不是作者签名。

## 验证与待验收

```powershell
node scripts/check-stage-templates.js
node scripts/check-frontend.js
# 已构建隔离服务并配置 HERTZ_BIN / PLAYWRIGHT_MODULE 后：
node scripts/check-stage-templates-browser.js
node scripts/check-stage-draft-browser.js
node scripts/check-ai-tasks-browser.js
```

离线检查覆盖固定版本拒绝、纯 create 与当前私有状态隔离、完整具名候选身份、原 owner 的预览/应用、收藏和分享往返。浏览器检查使用隔离 null 音频服务、真实前端与 Chrome，覆盖异步准备迟到、取消/应用、自动保存和收藏隔离、重开、版本禁用及 320px/390px 布局；侧边歌单在 320/390px 宽、500/760px 高时按悬停后的实际边界检查，并确认无歌词标题、导入 LRC 的活动歌词、stanza 流光歌词、设置按钮和播放条都不被卡片遮挡。截图前确认实际场景渲染像素，并输出横/竖屏截图到 `output/playwright/stage-templates/`。

这些检查不提供实际音乐频谱下的视觉评分、跨 GPU 表现或人工验收。下一步须用有代表性的真实歌曲分别审看横竖屏构图、歌词遮挡、运动舒适度、低频/高频响应及弱机帧门，再决定是否把候选晋级为正式模板。当前目录与样例不触发模型编排开放条件。
