# Hertz Studio 音质增强设计

> 日期：2026-11-23。状态：设计提案，供评审；尚未实施。
>
> Hertz 基线：`fe0baa05debd00561f70ab380077fa43805038e1`。参考本机 VCPChat `c3e4855e` 的 Musicmodules 与 Rust 音频引擎，以及 VCPToolBox `77220614` 的说明文档。
>
> 本文定义后续音频专项的行为、接入位置与验收条件。S1 重采样的现状仍以[音频重采样](audio-resampling.md)为准，项目完成状态仍以[路线进度](roadmap-progress.md)为准。文中的新增功能、接口及预算都是拟议设计，不能据此宣称已实现或声音已经改善。

## 1. 目标与设计取向

面向把 Hertz 当作主力播放器的本地曲库用户，优先解决三件事：调整 EQ 时声音连续、提高增益后减少失真、使用耳机或音箱时能够做有依据的频响校正。进阶用户可以主动选择染色效果，普通用户升级后保持现有设置和听感。

将“音质增强”拆成三种可独立判断的收益：

| 类型 | 用户收益 | 对应设计 | 证明方式 |
| --- | --- | --- | --- |
| 播放精度与稳定性 | 转换误差更小，调整参数时连续，峰值处理可预测 | 复用 sinc、连续 DSP、增益余量、真峰值保护、输出状态 | 参考信号、分块一致性、实时预算、真实设备 |
| 设备与听感校正 | 调整耳机或音箱的频响，缓和极端声道分离 | 参数 EQ、校正 IR、Crossfeed、小音量补偿 | 频响对照、正确的设备数据、同响度听测 |
| 主动音色加工 | 按偏好获得轻微温暖或柔和的音色 | 可选饱和器及干湿混合 | 谐波与混叠测量、同响度偏好比较 |

推荐默认保留当前声音；新染色和设备校正功能默认关闭。不复制 VCP 默认的 −12 LUFS、饱和器常开和浮点输出抖动策略。

本设计覆盖 Standard / Full、独立服务 / DBX 共用的 Rust 播放逻辑和设置入口。Windows 独占输出另有平台准入；LAN 另有呈现和共同处理约束。浏览器界面继续控制服务端播放，不新增 Web Audio 播放器或第二条 DSP 链。

本轮交付止于设计文档。完整 DSP 图编辑器、动态音频插件、全链 f64 迁移、AI 音频修复、DSD/DoP、新解码格式和强制升频不进入该设计的实施承诺。

## 2. 已有能力与具体缺口

### 2.1 当前源码事实

| 已有能力 | 源码依据 | 本设计的处理 |
| --- | --- | --- |
| 共享解码、混音和 DSP | [`render.rs`](../crates/vmusic-audio/src/render.rs)，`RenderCore`、`render_decks`、`write_samples` | 保留为单机和房间的共同实现 |
| 固定比例流式 sinc | [`resample.rs`](../crates/vmusic-audio/src/resample.rs)，`Converter`；[`Cargo.toml`](../crates/vmusic-audio/Cargo.toml) | 保留锁定的 Rubato 0.16.2，补实际听测，不重做 S1 |
| 六段峰化 EQ | `render.rs::EQ_BANDS`、`BiQuad`、`EqBank` | 保留 60 / 150 / 400 / 1000 / 2400 / 6000 Hz 的默认布局和 Q=1.2 |
| 局部双精度 | `BiQuad` 的系数、历史与级联计算使用 f64，输出转回 f32 | 继续按误差决定精度，不将已有 f64 工作重复立项 |
| ReplayGain 与防削波增益 | [`state.rs`](../crates/hertz-studio/src/state.rs)，`DspConfig`、`anti_clip_gain`、`current_loudness`；曲库保留 RG 标签 | 保留 off / track / album 和无标签时的现有语义 |
| 设备域 EQ、增益与软限幅 | `render.rs::write_samples`、`soft_limit(sample, 0.98)` | 首期保持顺序；真峰值阶段再替换末端策略 |
| 本机 float32 输出 | [`cpal_backend.rs`](../crates/vmusic-audio/src/cpal_backend.rs)，`CpalBackend` | 保留为跨平台基础路径；当前无需整数抖动 |
| 房间原生设备时钟 | [`scheduled_output/wasapi.rs`](../crates/vmusic-audio/src/scheduled_output/wasapi.rs)、[`receiver.rs`](../crates/hertz-studio/src/room/receiver.rs) | 保留独立 Receiver、唯一设备网格和原生时钟；当前 WASAPI 会话采用共享模式 |
| 设置服务端持久化 | [`routes.rs`](../crates/hertz-studio/src/routes.rs)、[`rpc/playback.rs`](../crates/hertz-studio/src/rpc/playback.rs)、`vmusic-store` | HTTP/RPC 收敛到同一音频设置应用函数，继续使用 SQLite |

目前 PCM 队列、重采样和设备接口主要使用 f32。现有 EQ 已有局部 f64，升级价值需要通过具体误差和处理行为判断，不能由位宽标签推断。

### 2.2 本次静态核查发现的设计风险

1. `Shared.filters` 是 `Mutex<Option<EqBank>>`。控制端重建 EQ；回调 `try_lock` 失败或参数签名不匹配时跳过 EQ。应改为继续使用上一份完整滤波状态，避免参数争用改变某一块的音色。
2. EQ 更新创建新滤波器历史，没有专门的参数平滑交接契约。新方案需覆盖持续音、瞬态和快速调参；本次没有运行复现，不能把静态风险当作已经测得的爆音。
3. 末端软限幅按样本幅度工作，尚不能提供采样点之间的真峰值上限。
4. HTTP 与 RPC 的 DSP 更新重复持久化和下发逻辑；`set_dsp`、`set_crossfade` 的后端错误被 `.ok()` 忽略。设置响应无法证明实际生效。
5. 现有六段 EQ 只开放增益；频率、Q、设备校正 IR 和真实输出状态尚无对应完整用户契约。

这些风险决定先做连续性和生效反馈，再引入更复杂的声音处理。

### 2.3 从 VCP 借鉴什么

VCPToolBox 的说明指向 VCPChat 的实际音乐窗口与 Rust 引擎。本次借鉴以处理流程和源码契约为依据，未通过听测比较两者的声音。

| VCP 的设计 | Hertz 的采用方式 | 阶段 |
| --- | --- | --- |
| f64 DSP、高质量 Rubato 重采样 | 保留 Hertz 已有局部 f64 与 Rubato 0.16.2；按误差和设备证据评估进一步改动 | Q0 |
| 连续处理链、控制端准备、音频端采用与回收 | 修正现有 EQ 交接，建立固定链及有界状态生命周期 | Q1 |
| 参数 EQ 与响度控制 | 先开放六段 frequency/Q 和余量；R128 与已有 RG 明确区分来源 | Q1–Q2 |
| 真峰值限制 | 引入可选保护，并先解决 lookahead、媒体位置和 EOF | Q2 |
| WASAPI 独占及格式协商 | 扩展原本机设备适配，报告请求和实际值 | Q3 |
| IR、Crossfeed、动态响度及饱和 | 按设备校正或个人偏好分别准入，默认关闭 | Q4 |
| 抖动与噪声整形 | 仅在真实整数终端量化时加入 TPDF；噪声整形继续单独评估 | Q3 / 后续 |

不直接沿用其全链精度、默认响度和常开饱和器，不以 Rubato 版本号或效果数量作为音质证据。

## 3. 方案比较与推荐

| 方案 | 优点 | 代价与适用条件 | 选择 |
| --- | --- | --- | --- |
| 单个音效逐项增加 | 首个功能改动小，容易针对一个场景验证 | 若仍共用当前滤波锁和错误处理，后续功能会重复处理交接、反馈与余量 | 适合作为交付粒度；先统一必要接缝 |
| 在现有 RenderCore 内建立固定处理链，分项开放 | 单机/房间复用算法，参数与历史分离，能明确阶段和资源边界 | 需要先调整 DSP 状态交接，延迟型处理器另做时钟设计 | 推荐 |
| 引入完整可编排 DSP 框架并扩大精度/输出能力 | 灵活配置任意处理组合 | 增加协议、调度与平台维护面，超出当前产品对完整 DSP 图的范围 | 当前不采用 |

推荐方案保留既有播放、队列和设备所有者。新代码模块仅承载处理器与应用函数，不成为另一套播放器；每阶段可独立验收和停止扩围。

## 4. 架构与处理顺序

### 4.1 首期链路

```mermaid
flowchart LR
    A[源域解码] --> B[每个 deck 独立 sinc 与声道映射]
    B --> C[设备域队列与交叉淡化]
    C --> D[连续六段参数 EQ]
    D --> E[既有增益与可选余量补偿]
    E --> F[既有软限幅]
    F --> G[float32 设备输出]
```

保留 S1 的设备域顺序，避免为模仿 VCP 先把 EQ 搬到源域。当前 crossfade 中的曲目增益归属与下一曲资格也保持原契约。

### 4.2 后续目标链路

```mermaid
flowchart LR
    A[解码与既有采样率转换] --> B[既有队列与混音]
    B --> C[参数 EQ 与校正 IR]
    C --> D[可选 Crossfeed 与动态响度补偿]
    D --> E[增益及可选饱和]
    E --> F[真峰值限制]
    F --> G[终端格式转换]
    G --> H[设备输出]
```

图中的可选处理器仅在对应阶段通过验收后接入。真峰值限制位于所有改变样本幅度的处理之后；整数抖动仅属于终端量化。新增降采样或设备率转换时，限制器必须覆盖转换后的最终浮点信号，不能用转换前的限幅结果保证输出真峰值。

这张图描述后续目标，不改变当前重采样顺序、房间转换位置或既有时钟资格。

### 4.3 职责

| 位置 | 职责 | 约束 |
| --- | --- | --- |
| `hertz-studio::AppState` | 队列、播放模式、保存的音频偏好、配置 revision | 沿用 `play_commit` 与本地/房间门禁 |
| 音频设置应用函数（拟议） | 校验、事务保存、准备与下发、HTTP/RPC 共用返回值 | 不持有样本历史，不执行 DSP |
| `vmusic-audio::actor` | 串行控制、准备参数、输出生命周期与资源回收 | 系数和资源准备不在输出回调执行，不吞下发错误 |
| `RenderCore` 共用的 `DspRuntime`（拟议） | 固定处理顺序、滤波历史、块边界参数采用 | 生命周期由原渲染 owner 管理，可变历史只交给实际输出执行者 |
| `CpalBackend` / 平台输出适配 | 设备会话、格式协商、终端量化 | 不复制混音、EQ 或业务队列 |
| 房间 Producer / Receiver | 共同渲染与本机转换、调度 | 继续区分渲染事实和呈现事实 |
| 前端设置页 | 草稿、能力说明、保存/生效反馈 | 不建立音频时钟、播放器或另一份持久化配置 |

`RenderOutput` 当前仅持有共享状态。首期需将 DSP 可变历史交给实际渲染执行者：本机为活动输出回调持有的可变运行态，房间为 Producer 串行 pull 持有的可变运行态，使用同一处理实现。`RenderCore` 继续管理原时间线和交接；同一运行态不能同时被 callback 和 pull 推进，也不能通过给 `Shared` 换一种可争用锁来实现“连续处理”。控制侧只发布准备好的参数。

## 5. 首期：连续参数 EQ 与增益余量

### 5.1 六段参数 EQ

沿用现有六段，开放每段的中心频率、Q 和增益。首期只支持 peaking 类型，先保证行为可测；增加段数、shelf 类型和任意编排分别评估。

| 参数 | 拟议范围 / 默认 | 行为 |
| --- | --- | --- |
| 段数 | 固定 6 | 旧客户端与已有曲线保持槽位对应 |
| 中心频率 | 20–20000 Hz；启用且非零的段还须小于当前处理率的 `0.45 × sample_rate` | 新接口越界明确拒绝；格式不满足时报告未应用，不静默移动频率 |
| Q | 0.25–8.0；默认 1.2 | 准备阶段检查系数有限、极点稳定 |
| 增益 | −12–+12 dB；默认 0 | 每个声道独立历史，所有段使用同一配置快照 |
| 手动前级 | −24–+12 dB；默认 0 | 保留现有前级语义 |
| EQ 启用 | 从已有曲线迁移；全零曲线可直接旁路 | 关闭时保留曲线，重新开启不清空用户值 |

继续使用 f64 系数与滤波状态；PCM 运输保持现有 f32。新实现的默认频率、Q、增益响应须与现有 EQ 对照，不引入隐藏的响度补偿。

关闭的 EQ 和零增益段不因较低处理率而阻断播放。开启非零段或准备新设备格式时再检查该格式的频率约束；失败保留旧有效输出，并按第 9 节报告保存与应用结果。

### 5.2 参数采用与平滑

- 控制侧计算完整系数快照，携带配置 revision、渲染 generation 和处理格式。
- 输出端每块最多采用一份新快照；没有新快照时继续旧状态，不绕过 EQ。
- 用户前级、余量等可连续变更的简单增益采用 20 ms 样本斜坡。EQ 的频率、Q、段增益和启停采用 20 ms 的旧/新滤波结果交叉过渡，避免直接插值系数经过不稳定区域；曲目增益和 transport 淡变继续沿原所有者及混音契约执行。
- 新滤波状态的预热与交接需保留连续输入历史；不能只从零状态开始并依赖渐变掩盖误差。输入历史使用预分配环，候选上限 4096 帧；执行侧在固定工作额度内分块预热并追齐输入，当前链继续正常处理，不能在一个回调中集中补算全部历史。历史或 CPU 预算不足以满足极端参数切换的测量目标时，拒绝候选并缩小最终开放范围。
- 快速调参只保留最新完整需求；执行端最多持有当前和一个预热/过渡状态，过渡完成后才开始下一次交接，不为每次拖动创建滤波链。已被更新需求取代的回执不能把页面标成最新设置已生效。
- 音频端传参使用有界、可验证的交接机制。固定参数可用预分配快照槽；涉及堆资源的后续处理器采用准备/采用/退休交接。退休槽满时推迟新采用，继续有效旧处理，回收在控制侧完成。
- 初始化和第一块输出也必须覆盖零分配验证，不能仅靠“预热一次”排除首次线程局部初始化。

设备切换必须撤回旧输出的执行权限并完成交接，禁止两个回调同时推进同一滤波历史。新的设备准备失败优先保留旧有效输出；旧设备已失效则明确暂停并报告恢复入口。

### 5.3 可选自动余量

对六段级联响应在 4096 个对数频点估算最大正向增益 `G_eq_peak`，并与单段中心频点共同检查。首期公式：

```text
boost = max(0, G_eq_peak + user_preamp_db)
headroom_db = boost > 0 ? -(boost + 1.0) : 0
effective_preamp_db = user_preamp_db + headroom_db
```

1 dB 为候选保护余量。界面显示实际扣减，例如“为当前曲线预留 4.2 dB 余量”。此规则是保守的频响估计，不能替代瞬态和真峰值检测，也不覆盖任意后续 IR/饱和器。

只计算实际启用段的响应，关闭 EQ 时 `G_eq_peak = 0`。余量扣减作为独立的末端前衰减因子，不写回用户前级，也不经旧 `DspParams.preamp_db` 的 −24 dB 下限截断；否则多段重叠提升时会少扣所需余量。`effective_preamp_db` 用于显示合计结果，曲目增益的既有归属与范围保持。

曲目 ReplayGain 继续沿既有逻辑和峰值标签处理，不重复计算第二份 RG 增益。余量默认关闭以保持升级行为，用户选择“日常聆听”建议配置时才开启；余量变化同样平滑。

## 6. 二期：R128 测量与真峰值保护

### 6.1 离线响度测量

既有 `off / track / album` 保留为 RG 模式。新增 R128 是独立可选来源，界面区分“文件标签”和“本机测量”，不把测量结果写入用户音乐文件或伪造 RG 标签。该阶段的配置只选择一个自动归一化来源和一个曲目/专辑模式，不能同时叠加 RG 与 R128 增益。

- 推荐目标 −18 LUFS，用户可在 −24 至 −12 LUFS 内选择；默认仍关闭自动归一化。
- 使用 EBU R128 / BS.1770 的门限测量，记录 integrated LUFS、sample peak、true peak、完整源内容指纹及算法版本。
- 曲目模式使用一次全曲固定增益；专辑模式为完整选定专辑计算共同增益，保留专辑内动态差异。专辑结果未就绪时明确显示未应用，不逐曲冒充专辑模式。
- 计算结果受既有曲目增益范围和峰值余量限制；目标不可达时返回实际增益及限制原因，不把目标 LUFS 当成已经达到的输出响度。
- 缺少 R128 测量时继续播放，自动归一化增益为 0 dB，并显示“尚未分析”；不静默换用 RG。用户选择文件标签来源时才沿既有 RG 规则处理，包括已有专辑标签缺失时的曲目回退。测量就绪后的增益采用需经过原播放 owner 的合法边界和平滑，不能突然改变当前块；不等待整曲扫描才出声，不做不断追响度的实时 AGC。
- 首批仅分析可稳定读取的本地文件与播放 owner 已确认的完整缓存。选项本身不触发远程下载，不分析变化中的渐进 `.part` 文件。
- 复用[后台预算](adr/0003-background-work-budget.md)的总额度，响度工作最多占一个现有分析槽，不扩大全进程两个分析槽。播放预热拿不到额度即推迟；用户显式测量显示繁忙并可重试，不堆整库等待队列。
- 流式读取、解码和计量，使用固定工作缓冲，完整内容哈希随读取产生。取消后直到实际 I/O、计算与落盘退出才释放额度。
- 测量缓存由 `vmusic-store` 管理，以曲目、完整内容 SHA-256 和算法版本识别；哈希与解码绑定同一稳定源快照，读取期间源变化则丢弃结果。使用前复核来源身份，已检测到的指纹变化或算法版本变化使旧结果不适用，不能只凭路径相同沿用。保留每轨最新有效结果，旧记录在新结果成功写入后才替换。

新的测量元数据表、专辑身份和缓存清理在该阶段的实施计划中单独迁移与验证，不塞进前端 localStorage 或全局设置大 JSON。依赖需核对许可证、Rust 1.88 和 Standard/Full 编译矩阵。

### 6.2 真峰值限制

在既有末端软限幅位置提供两种明确策略：`soft` 沿用当前行为，`true_peak` 为通过验收后可选的新策略。正常播放只运行一种末端限制策略，不叠加两个独立压缩器。

建议起始参数：4× 多相 FIR 检测、5 ms lookahead、100 ms release、−1 dBTP ceiling、声道联动增益。独立的 8× 离线参考检测器用于验收，避免测量与实现共享同一错误。

lookahead 只用于检测和保护，不能标成已恢复录音动态。限制器报告真实增益衰减，用户能看到持续触发；频繁触发时提示减小前级或 EQ，而非继续自动提高响度。

接入前必须完成第 10 节的媒体时间、输出延迟和尾部处理。首批仅在本机输出通过这些条件后开放；房间仍保持既有处理，不能让本机验收自动扩大到 LAN。

## 7. 三期：输出设备与 Windows 独占

### 7.1 请求与实际格式

输出偏好由原设备所有者管理，与 DSP 偏好分别保存、分别报告：

| 字段 | 请求值 | 实际值 |
| --- | --- | --- |
| 设备 | 用户选择的设备或默认设备 | 实际端点身份、后端和连接状态 |
| 模式 | shared / exclusive | 协商成功的实际模式 |
| 采样率策略 | device；后续可选固定率 | 源率、处理率、设备率及是否转换 |
| 样本格式 | 平台支持的候选 | f32 / s16 / s24 等实际格式及 valid bits |
| 声音状态 | 用户播放/静音意图 | 活动输出、准备中、无设备、故障 |

默认保持共享模式和既有设备选率，不默认 96/192 kHz。固定升频只作为高级选项，在对应真实设备和转换组合有证据后开放。

### 7.2 独占生命周期

只扩展现有 `CpalBackend` 所属的本机设备适配，不将房间的 ScheduledOutput 会话复制为新的本地播放器，也不把房间模式租约当作 WASAPI 设备独占。

1. 用户显式选择独占，后台探测当前设备的率、声道、格式和 event buffer 支持。
2. 能力不支持或设备被占用时保持旧有效输出和用户草稿，显示原因与“继续使用共享模式”。
3. 采用前重新核对设备身份、模式和配置 revision；变更后的设备需要重新准备。
4. 旧流停止与新流启动有明确屏障和淡变，保证不会同时出声。
5. 无法保持旧输出时明确暂停；不自动宣称已经独占，不用其它设备静默替代。

首批只支持已核验的单/双声道 PCM 格式。Windows 11 x64 至少验证一个系统端点、一个 USB 设备，覆盖占用、拔插、休眠恢复、暂停、seek、设备变化与长期播放；实际名单和驱动版本随报告保存。其它 OS 仍保留各自共享路径，能力返回明确说明。

### 7.3 整数量化与抖动

当前 float32 路径不加入 TPDF 或噪声整形。只有设备实际采用整数格式时才有适用的量化阶段：

```text
最终浮点样本 → 可选 TPDF / 误差反馈 → 舍入 → 有符号范围钳位 → 按设备 valid bits 打包
```

首批整数输出仅开放 TPDF；默认 `auto` 只在最终整数位深转换时启用。浮点输出返回 `not_applicable_float_output`。不同时在 DSP 和 WASAPI 打包处量化，不把 32 位容器宽度当作 32 位有效信号精度。

每声道随机历史独立，暂停、seek、格式变化有明确复位规则。Lipshitz / F-weighted 等噪声整形属于再后续候选，需要额外验证噪声谱、稳定性与采样率适用范围；首批不提供未经核验的曲线开关。

## 8. 四期候选：设备校正与音色

这些功能各自单独准入，不因前几期通过而同时开启。

### 8.1 校正 IR 与 FIR EQ

首选明确的耳机/音箱频响校正场景，载入本机 WAV IR 或由频响曲线生成 FIR。IR 以应用数据目录中的受管资源 ID 引用，不用任意路径作为持续执行标识；导入复制不改变原文件。

建议入口边界：单文件 8 MiB、单/双声道、8–192 kHz、转换后每声道最多 32768 taps。文件读取、解码、IR 采样率转换、FFT plan 和分区准备均在控制/后台完成，过程可取消。长 IR 的分区候选为 256 帧；实际延迟与资源需测量，不能由分区大小单独承诺。

相位和延迟需分别定义：自产线性 FIR 可以报告已知群延迟；任意导入 IR 的内在相位不能简单由最大峰的位置推断。未知相位/延迟 IR 首批只允许独立预览并提示，不能进入有音画同步承诺的正式播放。默认不支持混响尾音和任意 HRTF 组合。

新旧核最多各一份，核切换先准备、再在块边界渐变；旧核由控制侧回收。加载失败保留旧核与声音，不把“已选文件”显示为“校正已生效”。IR 请求返回实际 taps、处理率、算法缓冲延迟、已知相位信息及预留余量。

校正 IR 默认关闭，不附送未经本项目授权或测量的“通用耳机改善”预设。设备校正数据必须注明适用型号、来源、目标曲线和测量条件。

### 8.2 耳机交叉馈送

借鉴 Bauer / BS2B 的低通串音与直达声补偿。仅双声道启用，初始 cutoff 700 Hz、干湿强度 25%；参数在 10–20 ms 内平滑。用户明确开启，mono 和不支持布局返回不适用原因。

验收检查左右对称性、静音声道串入频响、低频增益和极端左右录音听感；不以“扩大声场”描述该处理，不将它自动叠加到所有音箱。

### 8.3 小音量补偿

按等响曲线思路提供受限动态 EQ，默认关闭。使用 Hertz 内部可知的本机音量作为输入，不假设知道耳机灵敏度、系统音量或实际声压。

首批最大低频补偿 6 dB、最大高频补偿 3 dB，50 ms 参数平滑，计算余量并经过同一末端限制器。该效果按数字音量进行近似补偿，不能宣称实际完成 ISO 226 声压校准。提高音量时平滑回到中性。

### 8.4 轻微饱和

默认关闭；启用后建议 drive 15%、mix 10%，先提供一种可解释的软饱和曲线。通过 2×/4× 过采样及低通回转换控制非线性混叠，选择由实际质量/CPU 测量决定。

干湿路径必须对齐延迟，限制器位于混合结果之后。不同管型、磁带等名称仅在相应传递曲线经过验证后出现；首批不把单个 tanh 函数包装成所有硬件模拟器。

## 9. 配置、接口与实际生效

### 9.1 首期配置对象

首次引入增强契约时，使用一个服务端版本化 DSP 对象 `audio_quality_v2`。以下为首期结构示例；既有曲目 RG 增益、音量、播放游标属于各自运行态，不写入该偏好对象。

```json
{
  "schema_version": 2,
  "revision": "0",
  "eq": {
    "enabled": false,
    "bands": [
      {"frequency_hz": 60, "q": 1.2, "gain_db": 0},
      {"frequency_hz": 150, "q": 1.2, "gain_db": 0},
      {"frequency_hz": 400, "q": 1.2, "gain_db": 0},
      {"frequency_hz": 1000, "q": 1.2, "gain_db": 0},
      {"frequency_hz": 2400, "q": 1.2, "gain_db": 0},
      {"frequency_hz": 6000, "q": 1.2, "gain_db": 0}
    ]
  },
  "preamp_db": 0,
  "headroom_mode": "off",
  "loudness_mode": "off",
  "crossfade_ms": 0
}
```

后续阶段通过独立 schema 变更增加已准入字段；不提前接收 R128、IR 或独占等未实现选项。输出设备偏好继续由原设备配置域管理，不复制到两个 DSP 对象。

`revision` 使用十进制字符串传输，避免 JS 不能精确表达全部 u64；耗尽时明确拒绝写入，不回绕。首期 `headroom_mode` 仅接受 off / auto，`loudness_mode` 仅接受 off / track / album，`crossfade_ms` 为 0–8000 的整数。新契约拒绝非有限值、未知字段和越界值；已存对象超过 64 KiB 或版本不支持时报告配置错误，保留原数据。

### 9.2 兼容和事务

首次读取且不存在 v2 对象时，将 `dsp_eq`、`dsp_preamp`、`dsp_loudness_mode`、`dsp_crossfade_ms` 及旧 `dsp_loudness` 的已有迁移结果映射为一个候选。六段频率和 Q 保持原值，EQ 启用取决于旧曲线是否非零，所有新增效果关闭，保留当前响度与 crossfade。此时 `revision = "0"` 是旧存储的只读投影，返回 `configuration_origin = "legacy_projection"`，不声称 v2 已经落盘。

首个成功保存以同一 SQLite 事务写入包含新 revision 的 v2 对象并删除已迁移的旧 DSP 键；之后 `configuration_origin = "v2"`，v2 是唯一持久化来源。事务失败不替换内存偏好、不下发候选。备份导入使用相同校验和迁移，不能恢复为两套同时生效的键。

已有 `/v1/player/dsp` 作为旧字段投影保留。旧 GET 在 EQ 关闭时投影六个零增益，不改变保存的曲线；旧 POST 显式包含 `eq_gains_db` 时沿旧语义更新六个 gain，并按是否非零设置启用，不重置用户已经编辑的 frequency/Q。仅更新其它字段时不碰 EQ。旧接口保留原 clamp 和部分更新语义；需要新增字段的客户端使用新接口。

兼容代码只做字段映射并调用同一应用函数，不保留第二套 DSP 或错误处理逻辑。旧客户端没有 `expected_revision`，只能在原提交锁内读取最新对象并串行更新、递增 revision，不能承诺它具有新接口的冲突检测。该旧接口按现有 HTTP/RPC 契约继续支持，退休需单独完成客户端版本调查与协议决策。

### 9.3 新接口

拟议 `GET /v1/player/audio-quality` 返回保存偏好、实际应用信息与能力；`POST` 接受绝对值 patch 和 `expected_revision`。DBX 经既有 RPC 路径调用相同函数，既有 token/权限边界保持。

```json
{
  "expected_revision": "7",
  "patch": {
    "headroom_mode": "auto"
  }
}
```

返回值至少包含以下事实；不是只返回用户提交的对象：

| 字段 | 含义 |
| --- | --- |
| `revision`、`requested` | 当前存储投影的偏好及其修订；v2 保存须经事务确认 |
| `configuration_origin` | legacy_projection / v2；区分旧存储映射与增强对象已落盘 |
| `application_state` | stored / applying / applied / deferred / failed |
| `applied_revision`、`render_generation` | 音频端实际采用的修订和渲染代际；未采用为 null |
| `effective` | 当前 EQ/实际前级/余量/响度来源等有效值 |
| `output` | 实际后端、设备、处理率、设备率、格式、模式和活动状态 |
| `capabilities` | 逐功能 supported、available、scope、reason |
| `issues` | 稳定 code、说明和可执行的恢复步骤，沿用 request_id 诊断 |

patch 按对象成员作部分更新，`eq.bands` 必须提供完整六段数组并整体替换；不以数组位置猜测缺失段，不用 null 表示删除。空 patch 和未知字段明确拒绝。

应用流程：校验并准备候选 → 复核模式/generation/revision → 事务保存 → 发布候选 → 音频端块边界开始采用 → 平滑完成后确认。准备失败和 revision 冲突不保存。没有可绑定的输出格式时只校验逻辑参数并保存，格式准备留到恢复输出时，状态为 `deferred`。保存后输出故障时，偏好已经保存，但响应/事件明确为 `failed` 或 `deferred`，实际修订保持旧值；不得用通用“成功”掩盖部分结果。

`applying` 包括等待交接、预热和渐变；`applied` 只在当前执行者完成该快照的采用后报告，不能以控制消息入队代替。crossfade 的采用表示原播放 owner 已接受用于后续合法转场的值，不改写已经发生的混音；这与新 EQ/余量快照一起返回有效信息。已采用也不代表缓冲中的对应样本已经被设备播放，呈现位置仍由原输出 owner 报告。

暂停状态允许准备参数，尚未消费样本时返回 `deferred`，下一次有效输出采用后变为 `applied`。null 后端和无设备只证明偏好保存，不能报告有音频处理生效。

更新是绝对值操作。POST 不自动重试；超时先 GET 核对保存和应用修订，保留用户草稿。旧回执、旧设备或旧 generation 不更新当前状态。保存和应用状态通过现有事件通道推送，持续电平遥测至多 5 Hz，页面不可见时停止该订阅。

建议稳定错误 code：`audio_quality_invalid`、`audio_quality_revision_conflict`、`audio_quality_unsupported`、`audio_quality_prepare_failed`、`audio_quality_apply_failed`、`audio_output_unavailable`。房间模式继续复用原本地播放门禁的错误，不另建绕过入口。

## 10. 延迟、尾部与一起听

### 10.1 统一处理语义

固定 EQ/增益保持一进一出，首期新增算法延迟为零。涉及块转换、lookahead、卷积的后续处理器必须声明：

```text
process(input, output) -> consumed_frames / produced_frames / state
finish(output) -> produced_frames / state
reset(reason) -> 清理不连续流的历史
latency -> 带采样率域的算法缓冲延迟
tail -> none / finite（带采样率域）
```

不为固定 EQ 强行套完整通用插件图。整数帧计数、`finish` 上限和零进展次数均有界；格式变化时重新准备，不能将输入帧、设备帧和纳秒直接相加。

自然 EOF 先排出属于真实媒体的延迟内容，再提交结束；seek / 新 load / stop 清掉旧延迟内容。暂停保留可恢复的滤波历史与尚未呈现的真实帧；睡眠定时的最终静音门禁继续覆盖所有新增延迟缓冲，不在恢复后放出旧音。

lookahead 的前导延迟补偿只依据新处理器自己的合同。S1 当前 Rubato 的 `output_delay()` 不代表应删除的静音帧，沿用[现有脉冲定位约束](audio-resampling.md)。

第一批正式 IR 只做校正：整体媒体区间不因 IR 尾部增长。流式执行按已知群延迟作有限预滚，真实 EOF 时有界补零排空，再裁剪到约定媒体区间，不要求整曲预渲染；普通混响尾音另立需求。gapless 过程中保持共同处理历史，不能在每个曲目边界清零；普通换曲和 seek 是不同语义。

### 10.2 本机呈现

真峰值/卷积引入延迟后，源帧消费位置不能直接充当已听见的位置。由原音频 owner 持有媒体帧至输出帧的映射，报告扣除尚未呈现处理延迟的媒体位置；曲名、Ended 和后继事件都需与实际输出边界对齐。

实现需覆盖开头、结尾、极短曲、暂停恢复、seek 和同率资格 gapless。无法保持这些条件时不开放新处理器，保留已验收处理；不通过提早 Ended 或删样本隐藏延迟。

### 10.3 LAN

遵守 [ADR-0011](adr/0011-lan-rendering-and-output-ownership.md)：共同 EQ、RG 和其他共同 DSP 在 Producer/RenderCore 只处理一次。Receiver 继续负责一次源相位/设备率转换和本机音量，成员不重复套同一 EQ、响度或饱和器。

- 首期新设置接口仅允许 local 模式写入；房间内不从本地设置入口改已共同渲染的 PCM。原房间处理继续采用入房时已准备、能由既有房间契约表达的有效配置；新增 frequency/Q 和自动余量的房间采用需另过 LAN 准入。若本机配置超出房间能力，入房前明确说明并要求选择兼容配置，不静默改曲线或丢弃本机偏好。
- 房间 fixed/native 模式和跨率能力按当前[原生采样率设计](lan-native-sample-rate.md)处理，不能采用历史“仅固定率”的状态描述。
- 新增延迟型共同 DSP 要在 Producer 准备期间完成启动预滚和输出帧映射；已 Commit 的 PCM 前缀不撤回，参数变化只进入合法未来边界。
- 设备转换可能产生新真峰值；要在每端保证真峰值，须在 Receiver 转换后增加受原所有者管理的终端保护并计入设备网格。这是独立 LAN 增量，不能由 Producer 限幅推断每端已安全。
- 私人耳机 IR、Crossfeed 和独占模式首批不在房间开启；开启它们需要每端延迟、状态和余量设计，不能在已提交队列上临时插入个人处理器。
- 原生 PCM、输入和输出预算、关房/退出屏障保持。DSP 的缓存、过渡副本与在途帧必须另外计量，不能把处理状态免费塞入 3 秒 / 8 MiB 的既有 PCM 上限。

上述限制是阶段能力范围；界面显示“当前一起听暂不支持该处理”，不显示为已经使用本机增强。

## 11. 设置体验与默认值

复用现有“设置 → 音效与均衡器”，沿用[当前单一 Hertz 布局和按钮契约](ui-layout-contract.md)。不新建播放器，不恢复退役皮肤，不将桌面组件专用 DESIGN.md 配色直接套到主应用。

页面分四组，按能力逐步出现：

1. 当前声音：保存/生效状态、实际设备与格式、可选的同响度对比。
2. 均衡与音量：六段 EQ、展开后的 frequency/Q、前级和余量、RG / 后续 R128。
3. 耳机与音色：已准入的 IR、Crossfeed、小音量补偿和饱和；默认折叠。
4. 输出：已准入的共享/独占、真实采样率与格式、整数抖动适用说明。

| 功能 | 默认策略 |
| --- | --- |
| 现有 EQ / preamp / RG / crossfade | 保留用户值；新安装分别为零曲线 / 0 dB / off / 0 ms |
| 自动余量 | off；用户选择日常建议配置才开启 |
| 真峰值策略 | 首期保留 soft；后续资格通过后作为用户可选策略 |
| R128 | off；开启后建议 −18 LUFS |
| IR / Crossfeed / 动态响度 / 饱和 | off |
| 输出与采样率 | 保留既有共享模式与设备策略；不强制升频 |
| 整数抖动 | 当前浮点输出不适用；整数输出阶段采用 auto |

首期延续“编辑草稿 → 保存”的模式，保存后的音频采用执行平滑；重置只重置草稿。实时试听和同响度对比作为后续独立交互增量，上线前需定义临时层与保存 revision、输出 generation 的绑定和撤销规则。试听不写数据库，不与保存请求并发生效；关闭或取消恢复当前已保存配置，不能恢复已经过期的快照。音量、睡眠定时和 crossfade 不被音色预设/对比重置。

对比旁路关闭 EQ/IR/音色效果，保持用户音量、曲目响度来源及末端安全保护。对比双方采用共同的固定衰减，避免移除余量时突然增大音量。未测得双方综合响度时明确标注未对齐，不能据这种比较声称更好。

键盘可操作所有数值和开关；曲线之外还有可编辑数值；失败反馈靠文字和控件关联说明，保留用户草稿。覆盖 390 px、200% 缩放、深浅主题、HTTP/DBX、断连和迟到回执。只在 `applied_revision` 对应当前保存修订、渲染代际匹配且 `application_state = applied` 时显示“已生效”；暂停或无活动输出另外显示当前声音状态。

## 12. 预算与验收

### 12.1 拟议资源预算

以下为实施候选目标，需在指定设备与 release 构建上测量；不宣称当前已满足。

| 项目 | 首期 / 后续候选预算 |
| --- | --- |
| 音频热路径 | 无堆分配/释放、无阻塞、无磁盘/网络/数据库操作；参数争用不跳过有效 DSP |
| 处理配置 | 一个活动配置、一个过渡配置、一个最新待处理需求；不会随拖动次数增长 |
| 首期 EQ | 0 帧新增延迟；44.1/48/96 kHz 单/双声道为首批质量矩阵 |
| DSP CPU | P99 不超过实际输出块期限的 25%；同机基线和最坏块另报，不能用平均 CPU 替代 |
| 真峰值 | 算法增加延迟目标 ≤12 ms，报告 lookahead 和检测滤波贡献 |
| IR + 真峰值 | 可知的处理/缓冲延迟合计目标 ≤40 ms；超限不进入首批正式播放 |
| 后续 DSP 工作内存 | 单本机处理实例目标 ≤16 MiB，包含核、FFT、历史、过渡与退休；不包括原解码器和既有 PCM 队列 |
| 响度分析 | 流式工作内存目标 ≤32 MiB；最多占一个现有分析槽；不整曲展开 PCM |
| 遥测 | ≤5 Hz，隐藏页面不订阅，不在回调格式化 JSON |

超过资源预算先拒绝更复杂的配置或保留旧有效配置并说明，不在播放中静默改音色、降低滤波质量或移除处理。

### 12.2 验收矩阵

| 场景 | 可观察的通过条件 |
| --- | --- |
| 当前行为回归 | 默认/迁移设置保持 RG、preamp、crossfade 语义；中性有限输入不新增音色处理；保留既有 PCM、压缩 trim、EOF/seek 回归 |
| EQ 稳定性 | 全范围系数有限、极点稳定；既有中心频率/Q 响应偏差 ≤0.05 dB；新参数响应对独立解析参考误差 ≤0.1 dB |
| 参数连续性 | 稳态音、脉冲、噪声及相反极限曲线切换；结果与独立的完整块过渡参考一致；无非有限输出、无争用导致的未滤波块；同响度人工确认无额外点击 |
| 分块与历史 | 固定参数下输入块 1 / 127 / 512 / 1024 帧和碎片组合产生等价序列；更新测试按同一绝对帧边界比较，并另测块边界采用；reset 清历史，pause 保留可恢复状态；所有进展与结束次数有界 |
| 余量 | 多段重叠增益、前级提升、未知峰值标签与 crossfade；实际扣减符合公式，用户关闭不清空曲线，开关过渡无突跳 |
| 真峰值 | 独立 8× 参考检测器测指定反相/高频/相关 crossfade 压力集；−1 dBTP 设置下测得峰值 ≤−0.9 dBTP；衰减、声道联动和延迟记录正确 |
| R128 | 已知 LUFS 参考曲误差 ≤0.2 LU；专辑共同增益保留差异；缺测量不阻断播放；源指纹/版本变化使缓存失效 |
| EOF 和音画同步 | 已知 L 帧延迟只补偿一次，极短曲真实输出完整，事件对应实际听到的边界；seek/stop 不泄漏旧样本，不扩大原 gapless 资格 |
| 终端量化 | s16/s24 的正负满幅、valid bits 打包和舍入正确；float 输出不产生 dither；抖动噪声和左右相关性对独立参考验证 |
| 设置失败与竞争 | 非法配置/准备/事务失败不应用；保存后输出失败如实返回；多页面 revision 冲突不覆盖；HTTP/RPC 结果一致；null 不伪装生效 |
| 真实输出 | 出声、占用、拔插、休眠、切设备、暂停/seek/续播及 2 小时稳定播放；记录驱动/设备/实际格式/欠载及采样范围 |
| 交互与预算 | 首次和连续回调分配计数为零；以至少 10 分钟代表负载采集 CPU/P99/内存；390 px、200% 缩放、键盘及迟到回执通过 |
| LAN 独立准入 | Producer 一次处理、Receiver 不重复、延迟映射与 Commit 前缀不变；跨率/退出/静音/欠载按原门禁，另做真实跨机资格 |

验收指标只覆盖对应参考信号和设备，不能据通带、低投影或代码语言宣称 205 dB 的系统动态范围。

### 12.3 主观效果验证

选择 12 首合法本地参考曲，覆盖人声、钢琴、密集摇滚、电子低频、极端左右分离、安静尾音和高峰值压缩录音。保存原始信号、处理参数、输出格式、构建身份和固定同响度版本。

保真类先通过客观误差与播放连续性；设备校正类同时验证目标频响的改善；饱和/Crossfeed 按偏好评估。比较时综合响度差控制在 0.1 LU 内，固定增益，不用动态 AGC 做测试对齐；对齐产生的新峰值同样核验。

ABX 能检验是否可辨别，不能单独证明偏好或“更好”。没有可重复的收益证据时保留可选/实验状态，不默认替用户开启。真实耳机/音箱、弱机和跨 OS 的结论分别记录，不由 null、离线探针或浏览器界面测试替代。

## 13. 交付顺序与停止条件

| 阶段 | 交付内容 | 接入前的必要证据 | 停止扩围条件 |
| --- | --- | --- | --- |
| Q0：补现有基线 | S1 真实歌曲/设备与 EQ 当前行为测量 | 绑定当前产物，建立通带、连续性、CPU 与实际出声基线 | 基线存在播放/同步失败时先收敛既有问题 |
| Q1：连续 EQ | 单执行者 DSP 历史、平滑更新、六段参数、可选余量、保存/生效反馈 | 首期参考信号、争用/首次分配、迁移与 HTTP/RPC 回归 | 争用漏处理、切换不稳定、旧设置丢失或假生效 |
| Q2：测量与真峰值 | R128 缓存和明确峰值策略，分别交付 | 独立参考计量、延迟/尾部/媒体映射、真实输出 | 响度语义错误、旧音泄漏、音画/EOF 错位或预算超限 |
| Q3：Windows 输出 | 请求/实际格式、独占生命周期、终端整数 TPDF | 真实系统/USB 设备，占用/拔插/切换/长稳 | 静默回退、双流出声、格式或恢复无法核验 |
| Q4：按需求选一项 | 校正 IR、Crossfeed、小音量补偿或饱和 | 每项自己的算法/许可、设备数据、音质与预算 | 收益不成立、延迟/资源超限或需要未经定义的 LAN 变化 |

这些阶段是音频专项的建议顺序，不与 R0–R6 主线自动并行排期，不相加历史周数。Q1 是推荐的首个实现任务；Q2–Q4 各自需要按本设计收敛为对应范围的实施计划。

每阶段通过后才添加能力字段、设置控件和默认策略。实验关闭回到已验证的处理配置，保留保存的偏好与说明；软件降级通过既有备份/版本恢复流程进行，不同时写旧新键维持两套持久化来源。

若实际实施改变 DSP 可变状态归属、旧接口兼容、持久化 schema、设备会话或媒体映射，应在完成证据形成后更新相应 ADR；本文的提案不预先写成“生效”的架构事实。
