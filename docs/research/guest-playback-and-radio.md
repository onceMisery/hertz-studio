# 未登录歌曲加载与电台调研

2026-09-30。只读参考 VCPChat/Musicmodules 和 folia-major；未启动参考项目或读取其用户登录凭据。

## 结论

Folia 有明确的游客路径，具备在平台允许范围内未登录搜索及获取音频的实现；这不等于所有歌曲、VIP 或无损都能匿名完整播放。VCPChat/Musicmodules 的核心来源是本地文件与 HTTP/WebDAV，聚合主要用于歌词，不能用它证明第三方在线歌曲能匿名取流。

本次直接按 Folia 参数请求酷狗公开匿名搜索（不带账号 cookie）得到 HTTP 502。参考目录未安装 node_modules，网易云 API 还需要其 Electron 后端或显式配置的 API 服务，因此本轮不能声称已成功运行 Folia 的完整游客播放链路。上一轮 Hertz 的多平台 HTTPS 请求与 Python 直连都在当前环境中失败，网络问题与账号权限必须分别判断。

## Folia 的具体实现

| 路径 | 行为 | Hertz 差距 |
| --- | --- | --- |
| `src/services/netease.ts` 的 `fetchWithCreds` | 未登录时调用 `/register/anonimous`，复用独立游客 cookie；收到 301/401/403 后清除游客会话 | Hertz 只读取现有账号 cookie，没有完整游客会话生命周期 |
| `netease.ts` 的 `cloudSearch/getSongUrl` | `/cloudsearch` 搜索，`/song/url/v1` 获取音频，空 URL 不算可播放 | Hertz 使用另一组直接平台接口；不能简单照搬 API wrapper 路径 |
| `onlineMusic/kugouProvider.ts` 的 `searchSongs` 与 `kugouTransport.ts` | 未认证时走匿名搜索；认证搜索走另一分支 | Hertz 仍统一使用 WebFilter 搜索 |
| `kugouProvider.ts` 的 `getAudioSource` | 按音质及曲目引用尝试，最后使用公开移动端 playInfo；实际有 URL 才返回 | Hertz 已有移动端与多通道取流，不需要另造第二套播放器 |
| `onlineMusic/qqProvider.ts` | 搜索与取流分离，取流按音质降级；空地址、权限拒绝和网络错误区分 | 能否匿名播放仍取决于平台给不给对应歌曲地址 |

## 电台可以加入，但有两种产品含义

Folia 的实现是私人 FM，不是网络广播直播：

- 网易云默认 `/personal_fm`；有能力时使用 `/personal/fm/mode` 支持模式/场景，失败回到默认 FM。
- 酷狗 provider 实现 `personal_fm`；QQ provider 当前 `recommendations: false`，没有同等 FM 实现。
- `usePlaybackQueueController.ts` 在队列剩余约两首时补取下一批，接入同一个播放队列。
- `Grid3D.tsx` 自动加载电台列表的条件还包含 `activeUser`。虽然网易云 API 客户端支持游客会话，不能据此推断 Folia 首页未登录时就提供可用的私人 FM。
- VCPChat/Musicmodules 未发现私人 FM 或网络广播目录；检索到的 `role="radio"` 是歌词候选单选控件。

Hertz 现状：`Capability::PersonalFm` 只是预留枚举；收藏中的 `radio` 实际承载在线歌单。接入真正 FM 时应保留旧收藏兼容，清楚区分歌单和电台类型。

推荐实施顺序：

1. 先补齐游客会话与公开匿名搜索，并用“免费歌曲/受限歌曲、游客/登录、搜索/音频取流”矩阵验证；不把网络失败显示成要求登录。
2. 单独增加 FM 能力与取批接口，第一期网易云；酷狗按验证结果开放，QQ 不虚报支持。
3. 复用服务端权威队列，加入 FM 会话、补歌去重、下一首、退出/取消。补歌应由服务端负责，浏览器后台或关闭后仍能连续播放。
4. 游客可用性以真实接口结果为准；若目标是可靠免登录连续听，可另做公开曲库/本地歌曲的连续推荐，但名称应区别于平台私人 FM。

网络广播直播流属于另一条实现路线：需要电台目录、直播流协议、无限时长播放与重连语义，不能用私人 FM 的歌曲批次实现替代。

## 搜索分页修复

发现并修正前端统一请求 30 首而酷狗后端上限 20 首造成的提前结束分页。现在统一使用各源都支持的 20 首；增加满 20 首后加载下一页至 40 首的回归检查。`check-online.js` 共 235 项通过，HTTP transport 检查通过。

## 已实施：游客访问与私人 FM

以上差距表描述改动前状态。本次新增：

- 网易云独立进程内游客会话：成功缓存一小时，申请失败冷却 30 秒；不写入账号保险库、不把游客当作已登录。账号凭据优先。搜索、取流与 FM 的登录失效响应会清除游客缓存。
- 游客申请采用经典 eapi 参数封装，FM 采用 weapi `/api/v1/radio/get`；AES、匿名用户名有独立 Node crypto 固定向量验证。公开 API 包 4.40.1 的游客申请默认已改为 xeapi，本实现没有加入其公钥会话链，经典 eapi 的线上兼容性仍待当前网络之外验证。搜索/取流在游客申请失败时仍尝试已有公开接口。
- 酷狗游客搜索增加 AndroidFilter 公共签名通道，失败回到既有 WebFilter；账号搜索及现有多通道取流保持原链路。
- 网易云空音频 URL 不再直接断言“必须登录”；连接失败归上游网络错误。新版 `ar/al/dt` 元数据兼容旧版字段。
- `/v1/online/radio`：GET 返回状态和当前 FM 队列，POST 支持 `start/retry/next/stop`。首批成功才替换旧队列；服务端在剩余两首时补歌，按曲目 ID 去重，连续历史在切歌时压缩，避免无限增长。
- FM 按顺序推荐，不受普通队列的随机/单曲循环模式干扰；补歌失败时不回绕旧歌，可重试补歌后继续下一首。退出保留已加载队列，切换普通歌曲自动退出。会话和播放代际共同隔离迟到结果。补歌与音频预取并行，已有下一首时切歌不等待补歌网络请求。
- 在线曲库新增 FM 卡片，提供开启、下一首、重试补歌、退出、当前歌曲和失败提示。服务端负责续播，页面只同步状态；页面关闭不终止 FM。

本期是网易云私人 FM；未加入广播直播目录、直播流协议、酷狗 FM 或场景模式。

## 验证边界

本地 Rust 测试覆盖协议向量、元数据、队列去重、启动失败、旧会话失效、队尾与历史压缩；浏览器 fixture 覆盖鉴权失败、重试、切歌、退出、迟到响应与 320/390 像素布局。它们验证实现与交互，不证明上游允许游客取流。

最终隔离构建通过；Rust 212 项通过、1 项忽略，在线前端 235 项通过，资源接线 448 项通过，transport、CSS 令牌与两套最终构建浏览器检查通过。截图为 `output/playwright/radio-{1440,390,320}.png`。工作区其它音频/舞台改动保持原状，未提交代码或重启用户原有进程。

真实匿名探测：网易云搜索、取流与 FM 连接失败；酷狗搜索超时。CCmixter 搜索返回歌曲且能生成音频地址，但抽样音频请求返回 HTTP 403。因此没有把任何一次搜索成功写成“完整音频播放成功”，也未验证会员曲、无损或登录账号播放。探测原始摘要保存在忽略目录 `output/fm-live-probe.json` 与 `output/fm-live-audio-probe.json`，不包含 cookie 或用户令牌。
