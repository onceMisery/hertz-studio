## 原型逐页对应

| 原型界面 | 实现落点与状态 |
| --- | --- |
| `entry` | 大厅只突出创建/使用邀请，附近房间后移一层；最近房间取本机真实记录 |
| `discover` | 独立附近页；加载时禁用刷新并显示骨架；成功整表替换；失败保留上次结果；搜索按名称/查找码过滤 |
| `create-avatar` | 创建弹窗中的昵称、8 款可选头像、昵称首字回退、本机收听；复用网卡选择及高级设置 |
| `join-avatar` | 加入流程的可选头像步骤，保存/跳过均可回到邀请草稿，关闭后恢复原入口焦点 |
| `invite-panel` | 全页邀请面板，查找码与一次性邀请分开；参与角色与高级权限、复制、手动复制、二维码复用原逻辑 |
| `invite-waiting` | 展示已观察到的邀请：待回应/过期/撤销/已使用或失效；支持重新邀请；成员展示已加入 |
| `invite-received` | 解析真实邀请中的地址、完整指纹，匹配已发现的房间名；核验保留在同一个 dialog 内，取消保留草稿 |
| `invite-invalid` | 可识别的邀请/授权错误显示专门状态，提供粘贴新邀请与附近页出口；网络未知结果继续查询原加入结果 |
| `apply` | 申请弹窗展示房间、地址、指纹、昵称、头像与本机收听选择；确认指纹后才提交 |
| `apply-pending` | 独立申请页；显示剩余时间、查询、清除本机记录及返回出口；大厅和附近页可重新打开结果 |
| `review` | 现场成员区、设置页与新申请弹窗复用同一审批状态；批准时选角色；保留焦点与稍后处理 |
| `waiting` | 无曲目时显示等待座位、真实成员/容量和邀请、点歌、队列入口；开始播放后切换现场 |
| `members` | 成员头像、本人/房主、连接/输出状态与权限摘要；细项折叠，移除保留二次确认与服务端校验 |
| `leave` | 成员确认框说明重新加入条件，并给出只调本机音量的替代方式 |
| `end-confirm` | 房主确认框列出受影响成员、观察到的曲目与时长；可关闭结束后的小结展示，直接回大厅；取消不发出退出操作 |
| `ended` | 服务确认退出后进入小结；人数、时长、曲目取本次实际观察；可保存 JSON、再开同名房间、返回应用 |
| `dissolved` | 真实终止信息中的房间结束、授权失效和其他断开分别呈现；不将所有异常统称为房主解散 |
| `full` | 可识别容量错误进入满员状态；发现数据若提供容量则显示数字并禁用申请。当前服务的发现元数据不含容量，见下表 |
| `reconnect` | 保留当前歌曲、歌词、队列和成员；显示断线横幅并禁用相关操作；恢复后继续消费权威快照 |
| `no-network` | 成功发现但列表为空与发现失败分开，提供同网络/AP 隔离/发现开关/防火墙检查及邀请入口 |
| `no-friends` | 无历史时显示解释性空态，无示例联系人或假历史 |

## 保留的增强

- 播放、共同队列、聊天继续查询原 operation 的结果；超时/重连不会重发未知写入。
- 房间、成员、实例与生命周期检查继续阻止迟到响应覆盖新会话。
- 原全共享曲库搜索、分页、在线/本机点歌、选曲分享回执、原生输出状态、媒体按键、歌词/封面、个人舞台与聊天复用保持原所有权。
- 邀请已生成但剪贴板失败时复用同一邀请，不重复生成。撤销状态只在服务确认后记录。
- 多网卡仍要求明确选择；单一有效局域网自动选中；不把回环地址默认当作可分享网络。
- 保留 44px 操作目标、键盘菜单、焦点锁定/归还、200% 缩放、减少动态效果、浅色与扩展主题。
- 历史只保存名称、参与者与曲目摘要，不保存邀请、指纹、申请凭据或连接凭据。最多 8 次历史、每次持久化 100 首；当前会话最多观察 2000 首和 64 位成员，不随轮询增长。

## 与原型的差异及原因

| 差异 | 实际行为与原因 |
| --- | --- |
| 跨设备头像 | 头像选择与展示已实现，但当前服务/配对协议没有头像字段；头像只在本机显示，并在选择时明确说明。其他成员回退昵称首字。未通过修改昵称或聊天消息偷偷传头像 |
| 邀请/申请有效期 | 继续使用服务返回的剩余时间；当前均为 300 秒，不写死原型的邀请 15 分钟/申请 30 分钟。改变服务授权期限属于协议与安全行为变更，不能仅修改倒计时 |
| 撤回申请 | 当前服务没有申请人远程撤回操作；提供准确标注的“清除本机申请记录”，保留“不撤销房主批准”的确认说明 |
| 房主转移 | 按钮禁用并说明可由朋友重新创建。当前唯一音频房主、TLS 身份、共享资源和审批权没有原子移交协议，本次未改写音频架构 |
| 邀请详情与失效原因 | 原始邀请只含地址、房间 ID、指纹和秘密；没有邀请人昵称、曲目、授权摘要、创建时间。只显示已知信息，剩余有效期以房主为准。服务移除的邀请无法区分被使用或被撤销，因此显示“已使用或失效”；本机确认撤销与已知到期可分别标记，不虚构具体接受人 |
| 满员与提醒 | 当前发现结果不含成员容量，配对拒绝可能是统一的 `pairing rejected`。不把拒绝一律断言为满员，不编造 8/8；只有明确容量信息时展示满员。没有后台空位提醒或向朋友发送提醒的服务，因此提供刷新/其他房间/新邀请出口 |
| 重连次数 | 原生服务采用退避重连并区分终止错误，没有原型的“最多 5 次，保留 10 分钟”合同；界面不伪造次数、缓冲仍出声或恢复期限 |
| 小结与歌单 | 提供本页面观察到的真实小结和 JSON 导出；共享资源 ID 不能当作本机永久歌曲 ID，故不将它们伪装成可播放歌单。历史“再开一间”只恢复房间名，不自动共享旧曲目或邀请旧成员 |
| 页面承载与样式 | 邀请作为全页 dialog 承载，保留已有模态焦点与返回行为；点歌等增强继续用抽屉。普通控件保留较原型更大的可点击面积；配色继续跟随全局 Theme，默认矿石黑与原型单色方向一致 |

上述服务能力缺口均未用假数据、无效操作或假成功填补；要实现跨设备头像、转移、远程撤回、准确邀请接受人和空位通知，还需要对应服务协议与双机验收。
