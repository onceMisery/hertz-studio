# 音质增强 Q1b–Q4 实施与资格记录

本记录续接 [Q1a](audio-quality-q1a.md) 与[父设计](audio-quality-enhancement-design.md)。用户要求直接实现后验证，不采用 TDD。2026-11-24 的代码在原播放器中接入参数 EQ、静态余量、峰值保护、离线响度、Windows 独占、短校正核和可选耳机音色；下述实现与软件验证不等同于整项音质或真实设备资格完成。

## 配置与兼容

`audio_quality_v2` 是唯一音质持久化对象。首次读取旧键保持只读投影；成功保存原子写入新修订并删除旧 DSP 键。对象版本 2 表达参数 EQ/余量，版本 3 增加末端保护与测量来源，版本 4 增加音色和校正资源。修订在所有 JSON 投影中都是十进制字符串；相同配置的应用重试保留原修订。

`GET/POST /v1/player/audio-quality` 和 DBX RPC 共用应用函数。未知字段、空 patch、非有限数值和不合格的处理格式明确拒绝；准备前后及提交区复核输出/播放代际。旧 `/v1/player/dsp` 仅映射字段，保持部分更新及 clamp，不重置自定义频率/Q。备份导入走相同对象校验，旧备份导入已有新对象时也原子迁移，并更新运行偏好。通用 settings 不能绕过音质与输出设置入口。

采用信息区分最新需求、旧有效配置、交接起点/目标/进度及渲染代际。同格式输出重建也会使旧采用回执失效。曲目增益仍属于播放 owner；`source_generation` 只在实际媒体替换时递增，普通暂停/续播/seek 不把同一来源的测量误当成新源，也不会让同 ID 的另一份字节复活旧增益。

## 参数 EQ 与余量

仍为六段 peaking。新参数处理的首批矩阵为 44.1/48/96 kHz、单/双声道；固定旧 EQ/前级的已有格式能力保留。新频率/Q/增益接受父设计逻辑范围，但活跃非零段须满足当前处理率和最多 2 秒输入历史的准备预算。低频高 Q 超限在保存前拒绝，不静默改系数。

两个滤波分支独立执行对应前级参与的曲目 clamp，再混合。普通增益变化在滤波前输入相同的条件下复制历史并作斜坡；跨 clamp 边界继续用原始 deck 历史预热。每帧最多追算 4 个历史帧，参数竞争保留旧有效处理。自动余量用 4096 个对数点、中心与端点及极值细化估算级联响应，加上已配置 crossfade 的提升和 1 dB 保护余量；衰减独立于用户前级，不受旧 −24 dB 下限截断。

## 峰值、延迟与媒体位置

默认仍为兼容 soft 策略。可选 `true_peak` 使用 128 taps、8 相 Hann 重建检测、5 ms 前视、100 ms 释放及声道联动。每个检测区间产生覆盖完整重建支撑区间的增益约束；处理后的输出另行检测。内部保护目标 −1.1 dB，独立离线参考验收目标 −1 dBTP。该保证仅针对本应用数字信号及约定的有限重建参考，不覆盖系统混音或 DAC。

每个真实帧携带媒体位置、转场、音量和 transport 淡变信息，穿过音色/IR/限制器后才更新呈现映射。EOF 有界排出真实媒体，seek/load/stop 清掉旧缓冲；暂停保留可恢复状态。最终音量为零和睡眠门禁覆盖全部延迟内容，整数量化不会向前导延迟、暂停零尾或硬静音注入抖动。

改变算法延迟的策略（限制器启停、饱和启停、不同群延迟 IR）在下一次定位或载入后采用，并明确显示等待原因。同延迟 IR 使用完整旧/新核的 20 ms 权重和为 1 的交接。仍有未呈现真实帧时拒绝替换设备流，保留当前输出，提示停止后切换；在撤回旧回调权限后再次复核，避免候选准备期间漏掉新增缓存。

## 离线测量与采用

锁定 MIT 许可的 `ebur128 0.1.10`。从裁剪后的源 PCM 取得 K 加权的 400 ms 块能量、100 ms 步长，进行绝对与相对门限计算；专辑合并完整成员的块能量，不平均各轨 LUFS。静音、门限块不足和低于门限有独立状态。采样率/声道布局、sample/true peak、完整 SHA-256、成员集合与算法版本存在专用表中。

分析占现有两个分析额度中的一个，且全进程响度 reader 同时只有一份。取消后许可保持到实际 I/O、计算、数据库提交或回滚及清理退出。限制为单源 2 GiB、单轨 6 小时、专辑 128 成员、一百万门限块、120 秒期限；流式处理不展开整曲 PCM。完整进程工作集尚不能仅凭这些缓冲上限宣称通过 32 MiB 资格。

只分析本地普通文件或播放 owner 确认的完整缓存，不触发下载。Windows 的哈希、解码和采用绑定同一禁止写入/替换的文件句柄；当前/下一曲最多两个有期限候选，专辑成员的身份租约随选中源保持。不存在就绪测量时立即以 0 dB 播放，绝不暗中改用 RG。后台完成只准备候选；显式“应用当前曲目”由原播放提交者校验最初身份，再在自己的提交内恢复位置，后来的用户操作优先。

R128 下一曲用精确来源与固定增益传给原双 deck renderer；文件 RG 继续保留原先的同增益预备准入，不借新增测量扩大旧接口资格。元数据、删除、扫描和导入撤销尚未开始的候选，已经发声或完成提升的转场保留原 owner 的事实。非 Windows 自动采用目前明确不可用，稳定不可变快照仍待实现。

## 输出与音色

`/v1/player/output` 单独管理设备偏好。共享 float32 保留原选率策略；Windows 独占使用固定端点、事件缓冲及明确格式协商，报告容器位宽与有效位宽。首批整数格式为 s16/s24，TPDF 只在最后打包时按声道独立运行。候选失败恢复旧有效输出；启动恢复失败不改用默认扬声器，失效后可显式重选。设置落盘失败会补偿回原输出，补偿失败则保持不可播放。

交叉馈送为双声道 700 Hz 低通串音与直达声补偿，默认强度 25%；小音量补偿依播放器数字音量近似，最多低频 6 dB/高频 3 dB，并预留对应余量。软饱和仅一种明确曲线，4× 过采样、低通回转换、干湿延迟对齐，drive 与播放音量独立。这些处理全部默认关闭。

完整 IR/FIR 与 4× 过采样饱和首批只开放 44.1/48 kHz。96 kHz 保留参数 EQ、自动余量、真峰值保护、交叉馈送和小音量补偿；不对复杂处理静默降采样、截核或降低滤波质量。保存、核准备/导入/生成与输出切换沿 core 共用软件资格检查。拒绝请求保留原配置及有效输出；可关闭饱和并清空校正资源后保存，再选择 96 kHz。能力字段分别报告 `saturation` 与 `impulse` 的 `qualified_rates`、`reason` 和用户可读 `message`；设置页保留可编辑草稿和关闭操作。

WAV 校正导入复制到数据目录的受管 SHA-256 资源，不修改原文件，要求记录设备、来源和目标曲线。读取上限 8 MiB/32768 原始 taps；转换后正式播放首批只接受不超过 257 taps 的奇数对称线性相位核，最长已知群延迟约 2.90 ms（44.1 kHz）。保留原核电平定义，单独报告并应用保守余量。超预算或相位未知明确拒绝正式采用；未知相位临时试听沿父设计 §11 作为后续独立交互增量，当前能力明确返回 false。

`POST /v1/player/impulses/generate` 与 DBX 同路径从 2–64 个严格递增的频率/校正增益点生成 257 taps 的单声道对称核，两声道共用。支持 −24 至 +12 dB，按对数频率/dB 插值、两端保持；使用有限频域采样及 Blackman 窗，不自动反转测量曲线。线性与对数频点及控制点检查最大误差超过 3 dB 时拒绝；成功返回最大/RMS 误差、最坏频率、控制点实际响应和独立播放衰减，不能据此宣称全频率精确相等。改变输出率后若转换超出 257 taps 须重新生成，不能静默截断。

导入/生成/采用准备共用单槽。生成和导入请求携带 UUID，`POST /v1/player/impulses/cancel` 只取消匹配身份；配置内部准备使用私有身份。取消在有限计算和分块 I/O 间检查，系统调用内不可立即中断；工作许可保持到清理完成。完整 WAV 与描述经临时文件准备及硬链接发布，不覆盖同内容的已有设备/来源说明；相同重试幂等，描述不同则明确冲突。该发布方式要求数据目录文件系统支持硬链接。前端生成/导入仅填草稿，期间用户修改过的草稿不会被迟到结果覆盖。

## 当前证据与剩余工作

阶段日志位于本机 `output/audio-quality`；可复现命令、源码与二进制身份汇总在 [证据目录](../evals/audio-quality/q1b-q4-20261124/README.md)。历史失败保留，最终通过只替代其对应源码与条件的结论。

- 真峰值频率/相位扫描发现并修正了 EOF 检测带宽不足及增益约束支撑长度不足。Rust 的 180 个频率/相位组合及 72 个脉冲、噪声和突发组合通过，扫描最大值约 −1.094 dBTP；这不是全信号数学证明。
- Rust 1.88：音频 249 单元通过、6 项手动探针忽略，另有 7 项集成通过；null 后端 31 项、core 54 项、store 69 项、Hertz 974 项通过（6 项原有忽略），内嵌资源 1 项通过。Hertz Full all-targets、DBX Standard/Full all-targets 编译通过。新增回归覆盖不支持采样率的拒绝保持配置/输出，以及显式关闭复杂处理后的 96 kHz 切换。完整链首次与尾部回调有零分配/零释放检查。
- 浏览器参数设置 10 组、输出/分析/校正动作 9 组通过，使用生产控件与真实 Chrome，覆盖冲突草稿、失败重试、键盘、390 px/200% 缩放、取消、迟到生成、采样率能力解释和清除过期的表单错误；隔离夹具不能替代完整应用/DBX 的现场验收。ADR 契约 430 项通过。
- 性能早期失败包含超块期限记录。旧十分钟全链记录中，96 kHz 的 128/512 帧 P99 分别为 28.4025%/25.485%，均未达 25% 目标，是收窄首批复杂处理范围的依据。最终开放矩阵完成 600.51 秒连续调参、预热及同延迟换核：44.1/48 kHz 完整链四组 P99 为块期限的 13.55%–15.79%，96 kHz 基础链两组为 21.14%/19.24%；六组零超期限，最大块耗时 1.996 ms。分组的 P99、最大值、期限和具体处理范围见证据目录。另行复测同机旧六段渲染基线；它未节拍限速、未设置 MMCSS 且变更频率不同，不能直接用比值解释新增开销。完整链合成回调按 Windows Audio MMCSS HIGH 运行，不能代替所有主机或驱动时序资格，也未完成全进程 RSS 与端到端参数采用延迟的资格。
- 本机 Realtek 48 kHz 共享 f32 和独占 s16、24 有效位/32 容器的 s24 静音流程通过。独占 f32 被设备拒绝时共享输出保留，随后 s16/s24 可选，结束恢复共享。仍未验证真实有声同响度听测、USB/物理拔插、占用与休眠、2 小时长稳、跨 OS/跨机资格，`device_qualified` 保持 false。

本次采样率收窄的独立补充审查连续三次因模型服务容量错误中断，没有收到结论。协调者直接核对准入、参数发布、输出恢复、IR 身份/处理率、旧 EQ 兼容和表单恢复，并修复仍固定在 96 kHz 的旧手动分段探针；新的 48 kHz 分段诊断及最终音频回归通过。这些检查不构成独立补充审查，边界另记在 `review.json`。

旧共享构建目录混用工具链后出现缺少 `.rlib/.rmeta` 的错误；最终使用独立 `target/audio-quality-msrv` 及 Rust 1.88 完成以上服务/存储/音频/资源检查。旧更新器临时文件占用失败和原性能失败日志均保留。Aegis 工作记录 bundle 成功；全局结构检查仍有既有旧索引与 ADR 命名问题，其结论不替代当前代码检查。
