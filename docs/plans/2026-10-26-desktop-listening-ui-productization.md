# 桌面歌词、壁纸与一起听：UI 和交互产品化方案

日期：2026-10-26。状态：**完整设计提案，供评审和实施排期；本次未修改产品代码。**

用户已经明确：重点是 UI 和交互；一起听先把现有局域网体验做成熟，再考虑异地。本文按 Windows 桌面歌词 / 壁纸、电脑局域网一起听设计，小尺寸只表示响应式窗口，不表示手机已能收听。

阅读建议：第 1–3 节看判断与方向，第 4–5 节可直接交给设计和前端，第 6–9 节用于实现、排期及验收。正文标记 **F** 表示主要可用现有数据和命令完成，**B** 表示需要明确的宿主或服务支持，**L** 表示后续扩展，不进入首轮 UI 交付。

## 1. 先回答：为什么现在还像功能演示

产品化的关键是：用户能看到结果、理解下一步、确信操作生效，并在异常后回到正常使用。当前已有较丰富的功能，但界面仍让用户承担许多组织和理解成本。

| 观察到的问题 | 具体证据 | 对用户的影响 | 本方案改变 |
| --- | --- | --- | --- |
| 壁纸设置先展示来源和参数 | `wallpaper-settings.html` 依次是音乐来源、数据目录、启用、显示器、帧率、音乐响应 | 尚未看到效果就开始配置；难以判断是否值得打开 | 第一屏放桌面预览，常用属性靠近预览，数据目录进高级信息 |
| 壁纸预览、应用和运行状态不在同一语境 | `wallpaper-settings.js` 主要显示「已保存」「未应用修改」；预览打开另一窗口 | 保存了不等于显示了；用户需要到桌面自行猜测 | 分开显示「修改是否保存」和「桌面实际状态」，应用后明确目标屏和结果 |
| 歌词可调，但管理分散 | 浮层已有锁定、样式、隐藏；样式面板有行数、次行、字号、透明度、宽度 | 找回、调位置和修改外观依赖对托盘的了解 | 统一桌面管理入口；浮层留最短操作；定位进入明确编辑模式 |
| 一起听拥有五个同级页面 | `room-workspace.js`：大厅、播放、邀请、队列与聊天、成员与设置 | 进入后像管理另一个应用；邀请或点歌打断听歌上下文 | 保留工作区，以听歌现场为主；队列 / 聊天 / 成员在侧栏，邀请用抽屉 |
| 创建房间暴露网络与音频工程参数 | `room-view.js::mountEntry` 有网卡、端口、采样率、封面、发现、输出等 | 发起一次共同听歌需要先理解网络设置 | 默认只填昵称，房名可改；自动选择的结果可见，少数歧义才请求选择 |
| 邀请以权限矩阵和原始字符串为主 | 邀请页平铺七个权限开关，生成与复制分开，二维码居于核心位置 | 不知道该勾什么；电脑场景下二维码并非最顺手路径 | 用角色预设解释参与方式；一次邀请最多一个主动作；二维码降为次级 |
| 参与点歌需要跨多个功能区 | 共享歌曲在设置，入队在共同队列页；播放页仅显示四条队列预览 | 用户先学会系统结构，才能完成「我想点这首」 | 点歌抽屉统一选歌；完整共同队列在播放现场操作 |
| 输出状态用工程语言 | 顶部显示「输出时钟已就绪」 | 看见成功状态，仍不知道当前是否有声音 | 显示「可收听」「本机静音」「准备声音」「连接中断」；诊断里保留原指标 |

以上按读取时的工作树判断。2026-10-26 已有歌词舞台、弹幕、侧栏 Tab、创建 / 加入弹窗、主题菜单和可收起浮动播放条，应直接沿用；不能把旧截图当作当前界面仍未升级的证据。

## 2. 对标什么，以及选择哪条路线

### 2.1 对标的是使用方式

| 参照 | 采纳的体验原则 | Hertz 的具体落点 | 本轮范围 |
| --- | --- | --- | --- |
| Wallpaper Engine | 先看到内容和效果，再调整属性；显示器归属明确；后台行为有解释 | 桌面预览 + 属性面板 + 当前显示器 + 运行状态 | 先把已具备资格的星座壁纸和桌面歌词组织好 |
| Wallpaper Engine | 长期使用可以找回、暂停、恢复，设置与效果对应 | 统一桌面中心、托盘恢复、未保存状态、运行原因 | 单目标屏，恢复当前配置 |
| Spotify Jam | 从当前音乐发起；邀请简单；共同队列是参与中心 | 当前歌曲入口、邀请抽屉、点歌抽屉、队列点歌人 | 电脑局域网，使用现有授权和音频能力 |
| Spotify Jam | 房主和参与者知道自己能做什么；会话始终可见 | 可理解的权限预设、房间标识、主界面中的浮动播控 | 保留当前房主 / 成员体系，无新增账号社交系统 |

不把 Steam 内容生态、任意第三方壁纸、手机碰一碰、互联网连接、算法共同推荐搬进 UI 第一阶段。现有能力边界直接影响页面：只有一款壁纸时展示单款精品详情，不摆出大量不可用缩略图；手机没有接收能力时不把扫码宣传成「扫码即听」。

官方参照核对于 2026-10-26：[Wallpaper Engine](https://www.wallpaperengine.io/en) 描述显示器、性能策略、自定义和播放列表；[Spotify Jam 帮助](https://support.spotify.com/us/article/jam/) 描述从歌曲 / 歌单发起、邀请、共同排歌及房主控制。本文的线框、尺寸和优先级是针对 Hertz 的设计建议，并非竞品界面逐像素测量。

### 2.2 三条路线

| 路线 | 收益 | 代价与不足 | 结论 |
| --- | --- | --- | --- |
| A. 仅修改颜色、圆角、间距 | 改动小，短期观感改善 | 操作路径和认知负担基本不变 | 可作为局部工作，不作为总体方案 |
| **B. 重组现有能力，缩短核心流程** | UI 提升直接服务高频动作；复用已有能力 | 需要重排页面并补少量展示合同 | **推荐，作为本文默认实施方向** |
| C. 完整复制内容平台和社交产品 | 未来功能面广 | 新内容体系、账号、远程网络拖慢当前体验改善 | 留给后续单独规划 |

### 2.3 三条界面原则

1. 一屏只有一个主要任务。壁纸页是判断和应用效果，房间页是听歌和共同排歌。
2. 高级能力在需要时出现。网络参数、原生诊断、精确跳转和细粒度权限从主流程下沉。
3. 所有动作有可理解的结果。正在处理、完成、失败和结果未确认分别设计；返回页面与退出会话严格区分。

## 3. 两个功能共用的视觉与交互规范

| 项目 | 可实施规则 |
| --- | --- |
| 视觉归属 | 房间沿用全局 Theme 的 `--bg`、`--panel-solid`、`--text`、`--muted`、`--accent`、`--line`，不新增一套房间配色。桌面原生设置先保持已有中性深色，使用同样的排版和控件语义；没有主题桥接时不承诺同步全局主题 |
| 字体 | 沿用应用现有字体栈和 Windows 中文系统字体；先解决字阶、密度和排版，不为升级外观额外引入字体下载 |
| 字阶 | 页面标题 20/28、区块标题 16/24、正文与操作 14/20、辅助 12/18；歌词预览 28–40，舞台当前行按容器 28–44。数字时间使用等宽数字 |
| 布局 | 8px 基础间距；相邻控件 8/12、相关分组 16、区块 24。大型卡片只承载独立预览或主要内容，队列和成员使用连续列表 |
| 控件 | 桌面常用按钮高 36–40px，图标和触屏目标至少 44×44px；主要按钮表示下一步，常规动作低强调。破坏性动作移到更多菜单末尾 |
| 圆角 | 输入 / 按钮 8、浮层 12、主预览 16；减少整页大胶囊、大圆角嵌套和发光按钮 |
| 反馈 | 点击立即显示按下 / pending；超过 300ms 才出现加载提示，超过 3s 显示具体阶段和可用动作。时间阈值是 UI 设计值，不伪造业务进度百分比 |
| 动效 | 常规 120–180ms，抽屉 180–220ms；仅 opacity / transform。队列变动不大幅跳位；减少动态效果时停飞行弹幕和装饰运动 |
| 焦点与键盘 | Tab 顺序与阅读顺序一致；Esc 关闭最上层浮层并恢复入口焦点，不退出房间。菜单外点关闭；有未保存修改的编辑器需明确保留 / 放弃 |
| 空态 | 先说现状，再给一个能继续的动作：「还没有歌曲 · 添加第一首」「当前歌曲没有歌词 · 打开播放器查看歌词」 |
| 提示层级 | 行内错误用于当前动作；横幅用于持续故障；短暂 Toast 用于复制、保存等一次性反馈。每个错误都提供下一步，不把底层错误栈放进正文 |
| 无障碍 | 普通文字对比度至少 4.5:1，关键控件及大字至少 3:1；不只靠颜色表达状态。进度、音量、投票、锁定有可读名称和状态 |

全局快捷键暂不作为找回歌词的必要条件；原生支持尚未交付时，菜单上不展示一个无效快捷键。空格仅在播放区且焦点不在输入 / 按钮 / 对话框时控制播放，避免聊天输入误触。

## 4. 桌面歌词与壁纸：从参数窗口到桌面设置台

### 4.1 信息架构和入口

统一使用「桌面」作为管理入口，页面标题「桌面歌词与壁纸」。顶部三个页签：**壁纸 / 歌词 / 运行设置**。两个 surface 仍独立启用、独立显示状态，统一界面不要求同时打开它们。

入口：主应用现有设置区改为带当前状态的「桌面」卡片，主按钮「打开桌面设置」；播放更多菜单提供「桌面歌词」，有壁纸资格的空间场景提供「设为桌面壁纸」。托盘首项「打开桌面设置」，随后是歌词显隐 / 编辑、壁纸显隐、运行状态及退出组件。

**主界面与托盘都打开同一个原生管理窗口。** 不再维护另一份网页设置。组件未安装、版本不兼容或当前平台不支持时，在入口原位说明并给现有可用处理动作。

### 4.2 壁纸页布局

目标初始窗口 1120×740 逻辑像素；实际不超过当前屏幕可用区域。宽度 ≥1040 时预览和属性双栏，760–1039 时属性进入右侧可展开面板，<760 时预览在上、属性在下。底部应用区始终可见；预览为 16:9 或目标屏真实比例，不挤压成固定小缩略图。

```text
┌ 桌面歌词与壁纸                      壁纸：显示中 · 主显示器 ┐
│ [壁纸]  歌词  运行设置                                      │
├──────────────────────────────────┬─────────────────────────┤
│ 当前壁纸 · 星座                  │ 显示位置                │
│                                  │ [显示器 1 · 主屏  ▾]    │
│       与当前选择一致的桌面预览    │                         │
│       示意图标区 + 任务栏安全区   │ 流畅度                  │
│       预览 / 暂停 / 放大          │ 节能  均衡✓  流畅       │
│                                  │                         │
│                                  │ [✓] 随 Hertz 音乐律动  │
│                                  │ 没有音乐时保持环境动画  │
│ [显示桌面图标示意]                │                         │
│ 图标为构图示意，不读取真实文件    │ 高级信息 ▸              │
├──────────────────────────────────┴─────────────────────────┤
│ 未应用修改                         [放弃修改] [应用到桌面] │
└────────────────────────────────────────────────────────────┘
```

- **F** 用真实场景静态预览作为初始内容，不让每张缩略图各运行一个 WebGL 实例。
- **B** 「播放预览」使用唯一现有预览租约；首轮可继续打开独立预览窗，按钮明确叫「打开实时预览」。P1 再把同一租约 / renderer 集成到中心预览区域，旧独立实时预览路径随之退出。
- **F** 当前只有星座，就给星座一个完整详情。以后至少两款通过资格验收，再加「我的壁纸」筛选和缩略图列表；没有内容时不显示搜索、分类或下载量。
- **F** 目标显示器以编号、主屏标记和分辨率展示；拓扑小图由已有坐标 / 尺寸绘制，明确「一次只应用到一个显示器」。图块和下拉框控制同一选中值。
- **F** 「均衡」默认映射现有 30fps，「节能」15fps，「流畅」60fps；说明只是帧率上限，不卡片上展示未经测量的 CPU 或电量节省比例。
- **B** 「识别显示器」需要原生短暂编号浮层；没有该能力时先交付拓扑选择，不放空按钮。
- **L** 亮度、运动强度、图标避让、多屏独立应用和壁纸轮播不在现有配置字段内，不能只画一个滑杆就算功能；以后按场景参数资格逐项接入。

### 4.3 壁纸的完整交互规则

| 情境 | 界面和操作 | 确认结果 |
| --- | --- | --- |
| 首次进入 | 默认当前主屏、均衡、跟随 Hertz 音乐；当前未启用，主按钮「启用并应用」 | 点击前不改变桌面 |
| 调整参数 | 本地草稿立即更新数值；可刷新实时预览；底栏出现「未应用修改」 | 草稿不是已保存状态 |
| 应用 | 按钮显示「正在应用…」并阻止重复提交；保留原预览和参数 | 宿主确认配置后显示「设置已保存」，确认实际显示后显示「已应用到显示器 1」 |
| 应用时被全屏策略暂停 | 仍可保存，状态「已应用，当前因全屏应用暂停」 | 不假报「显示中」，也不要求用户反复应用 |
| 应用失败 | 显示原因和「重试应用」，草稿保留 | 不把配置失败、渲染失败和未显示混成同一错误 |
| 配置版本冲突 | 横幅「设置已在另一处修改」，提供「加载最新设置」；未提交草稿可继续查看 | 不自动覆盖另一入口的修改，首轮不做复杂字段合并 |
| 放弃修改 | 恢复最后确认的配置，结束当前草稿预览 | 无破坏性副作用，不需要二次确认 |
| 关闭 / 切换来源时有草稿 | 「保留编辑」「放弃并关闭」；需要应用时先回到页面应用 | 关闭不能偷偷应用；切换来源前处理草稿 |
| 显示器断开 | 当前屏保留为「未连接」，说明画面暂停；提供选择已连接显示器 | 不静默跑到另一块屏，也不清空用户配置 |
| 停止音乐 / 来源断开 | 壁纸状态仍可为「显示中」，附「音乐未连接，播放环境动画」 | 音乐连接与壁纸渲染分别呈现 |
| 隐藏壁纸 | 当前能力对应「隐藏壁纸」，状态「已隐藏」；入口变「显示壁纸」 | 不把当前隐藏命令包装成保留静帧的「暂停」 |
| 未来暂停 / 继续 | 仅在原生实现保留画面的停绘语义后开放 | 手动暂停与关闭功能分别命名 |

**B 状态支持：** 将管理状态已有的 visible、pageReady、monitorMissing、pauseReasons 和来源状态接入设置页。配置 revision 与实际运行状态分别使用字段，不从一条「已应用」文案推断显示成功。

### 4.4 歌词页布局与样式

歌词页沿用同一预览框，但主要展示歌词在桌面中的实际位置和可读性。预览顶部可切「深色背景 / 浅色背景」；不读取用户桌面截图。未播放歌曲时使用明确标注的示例歌词；有实际歌词时可切回当前歌曲。

```text
┌ 歌词：显示中 · 已锁定                                       ┐
│                                                            │
│              桌面预览                                      │
│              当前这一句歌词                                │
│              下一句 / 译文                                 │
│                                                            │
├────────────────────────────────┬───────────────────────────┤
│ [简洁单行] [双行跟唱✓] [双语]  │ 字号       32 px   −  +  │
│ [编辑桌面位置] [恢复默认位置]  │ 字重       常规 / 较粗    │
│                                │ 已唱颜色   ○  未唱颜色 ○ │
│ 次行无译文：显示下一句          │ 描边       颜色 / 粗细    │
│                                │ 不透明度   92%            │
├────────────────────────────────┴───────────────────────────┤
│ 未应用修改                      [放弃修改] [应用歌词样式]  │
└────────────────────────────────────────────────────────────┘
```

三个内置样式组合只使用已有 `LyricsConfig` 字段，不创建第二套歌词格式：

| 样式 | 具体初始值 | 适用 |
| --- | --- | --- |
| 简洁单行 | single、32px、字重 600、不透明度 .92、未唱 #FFFFFF / 已唱 #8FE3FF、2px #000000 描边 | 工作时阅读当前句 |
| 双行跟唱 | double + next，主行 32px，次行沿用现有比例；颜色、透明度和描边同上 | 跟唱与下一句预告 |
| 双语 | double + translation，其余同上 | 有译文时显示译文；无译文时按既有回退规则展示并明确说明 |

样式不修改用户位置、锁定状态、启用状态和音乐来源。调整预设后显示「自定义」，不要错误地保留原预设勾选。字号范围沿用现有 18–72px；键盘步进和输入校验一致。颜色不是必须修改项，默认就应在明暗背景上可读。

**B** 统一中心需要读取 / 提交歌词样式的宿主桥接和草稿预览；复用已有配置字段和 revision。当前浮层增减字号是即时命令，不能直接拿来做中心「尚未应用」的草稿预览，否则取消编辑会误改实际配置。

### 4.5 歌词编辑模式：把「锁住后找不到」变成可恢复的操作

1. 点击「编辑桌面位置」：打开实际歌词浮层、临时解锁并显示边框、拖动柄和尺寸提示；中心显示「正在桌面上编辑位置」。这是明确进入的编辑状态。
2. 拖动以屏幕可用区域为边界，位置吸附可见安全边；显示屏和任务栏边界留至少 16px 逻辑间距。拖动过程中不抢其它窗口焦点。
3. 编辑工具条只留「拖动」「样式」「完成」和更多菜单；鼠标离开且无键盘焦点时淡出。编辑中、拖动中、面板展开时不自动隐藏。
4. 「完成」提交位置，退出编辑并恢复进入前的锁定状态；首次设置推荐锁定，显示一次「已锁定，可从托盘或桌面设置再次编辑」。
5. 「取消编辑」恢复进入前的位置 / 锁定 / 显隐状态。`Esc` 必须在可接收键盘焦点的管理窗口或编辑控件里生效；无焦点的穿透浮层不能承诺能捕获全局 Esc。
6. 任何状态都能从托盘的「显示并编辑歌词」找回；设置中心提供「恢复默认位置」。移除原显示器后，恢复动作明确让用户选可用屏或主屏。

**F** 先改善工具条和找回文案，保留已存在的锁定、解锁和位置恢复命令。**B** 临时编辑事务、取消恢复、原生 resize / 边界吸附需要宿主支持，归 P1；不得仅通过 CSS 模拟真实窗口尺寸变化。

### 5.4 邀请：一句话说清参与方式

邀请从现场右侧打开 400px 抽屉，小窗为全屏面板。保留音乐现场，不跳去一张几乎都是说明文字的大页面。

```text
邀请朋友                                      关闭
在同一网络的电脑上打开 Hertz，即可加入

参与方式   [一起点歌 ▾]
可以点歌、投票和聊天；播放由房主管理

[生成并复制邀请]
尚未生成邀请

附近的朋友也可以申请加入
房间查找码  ABCD 1234                  [复制]
查找码用于申请，不能直接收听

高级权限 ▸          显示二维码 ▸
```

角色是现有权限的 UI 预设，不创建新的后端成员角色：

| 预设 | listen | queue | transport | volume | chat_read / send | invite |
| --- | --- | --- | --- | --- | --- | --- |
| 仅收听 | ✓ | — | — | — | ✓ / — | — |
| **一起点歌（房主签发默认）** | ✓ | ✓ | — | — | ✓ / ✓ | — |
| 共同控制 | ✓ | ✓ | ✓ | — | ✓ / ✓ | — |

共享音量和邀请他人保持高级授权，不随「共同控制」自动开启。预设下方实时用自然语言说明。手动改过任意权限后显示「自定义」。`queue` 当前代表完整队列权限，不能把它解释成「只能添加自己的歌」；如要更细权限，另作服务合同变更。

成员签发邀请遵守现有权限上限：只展示其实际可授予的组合。尤其当前成员邀请仅允许其持有的基础收听 / 聊天权限，不能因为成员自己有队列权限就显示可转授「一起点歌」。

具体行为：

1. 「生成并复制邀请」在一次明确点击中请求生成，回执成功后尝试复制。剪贴板失败则保留这份邀请并显示「邀请已生成，点击复制」，不能重新生成一份。
2. 成功后按钮改为「再次复制邀请」，旁边显示「单次使用 · 04:58 后过期」。有效期来自服务返回，不因打开抽屉重新计时。
3. 邀请已用或过期时，主按钮改为「生成新邀请」。本机已知被使用时立即更新；外部已消费但尚未获知时，以加入端的真实结果为准，不凭倒计时宣称仍可用。
4. 「修改参与权限」若已有邀请，先明确告知旧邀请的权限不会随表单改变；使用「撤销并生成新邀请」完成替换，撤销失败不能悄悄保留两种权限入口。
5. 同一网络多人加入优先使用查找码 + 申请审批；直接邀请仍是一人一次，不能当作群体永久链接。
6. 邀请原始字符串放「查看邀请内容」内，支持手动全选复制；不让长串字符成为页面主视觉。
7. 二维码作为次级辅助，提示需在支持的电脑 Hertz 中完成加入；当前无手机接收端，不用「手机扫码即可听」文案。
8. 关闭抽屉不自动撤销有效邀请；撤销有显式按钮和已撤销状态。签发失败只报失败，不能显示「已复制」。

### 5.5 加入：识别意图、逐步反馈、保留信任核验

「加入」面板主输入接受现有邀请串 / 邀请封装文本与 8 位查找码。输入后自动区分，给对应下一步：有效邀请→「加入房间」，查找码→「查找房间」。不要求用户先理解两种编码。

- 查找码只匹配当前真实发现结果；发现不到时说明「未在当前网络发现该房间」，提供刷新 / 改用直接邀请。现有能力不支持跨网解析，不能展示全网搜索进度。
- 填一次昵称；本机声音用「在这台电脑收听」开关，关闭时提示仍可参与获准操作。
- 首次加入同一房主必须核验主机地址和完整指纹。把核验融入当前面板的下一步，不再关闭对话框、弹确认、再重新打开；解释「请与房主核对以下身份信息」。不把昵称或短指纹当作可信替代。
- 已保存的房主使用现有凭据恢复规则；身份发生变化不能沿用旧信任，显示明确的新身份核验。
- 入房过程显示「正在连接」「等待房主批准」「正在准备声音」「已加入」，每阶段按实际事件更新；「取消申请」与「关闭面板」不同。
- 申请状态采用有界的只读查询：面板活跃时约 2s，60s 后降为 5s，取消 / 切房 / 页面离场终止；协议限流优先。返回后查询原申请，不重复提交新申请。
- 批准后按原授权加入；结果未知查询原状态。连接完成但音频未准备好时已进入房间，展示可理解的声音状态，不用无限 spinner 挡住队列和成员。
- 过期 / 已使用邀请分别写明，按钮「粘贴新邀请」。审批被拒绝时写「房主未批准此次加入」，不自动重申。

**F** 输入识别、面板分步和已有命令编排；指纹、权限和一次性授权继续由已有服务处理。

### 5.6 点歌：一处完成查找、选择和加入

入口固定在队列顶部「＋ 点歌」，空队列主动作「添加第一首」。点击打开点歌抽屉，默认聚焦搜索框；关闭后回到队列原位置。

| 用户 | 抽屉内容 | 主动作 |
| --- | --- | --- |
| 房主 | 已共享歌曲 / 本机音乐 / 已支持的在线来源；搜索作用于当前明确选择的来源 | 已共享歌曲「加入队列」；未共享歌曲「共享并加入」 |
| 成员 | 仅房主已共享的歌曲，显示真实元数据和可用状态 | 「加入队列」；无队列权限时显示原因 |
| 无可用歌曲 | 说明当前没有共享歌曲；房主可选本机歌曲，成员等待分享 | 房主「选择歌曲」；成员不展示无法执行的按钮 |

本轮优先实现当前共享歌曲和本机选曲入口，在线来源接入以并行中的在线一起听功能实际通过验收为条件，不能把它当作 UI 已有稳定依赖。

交互细节：

- 单击行只选中，不立即播放。明确的「＋」按钮入队；不会因为双击封面而突然切断全房间当前曲目。
- 发送后该行显示「正在添加」，确认后显示「已加入」和可用的队列位置。位置未知时只显示「已加入队列」，不编造序号。
- 一次点击只入队一次；已加入后需要再次选择「再加入一次」才重复点歌。重复实例在队列中独立存在。
- 房主「共享并加入」明确只共享选中的条目；分享成功但入队失败时提示「歌曲已共享，尚未加入队列」，下一次只补缺失步骤。
- 不抢占当前搜索焦点，允许连续添加；批量选择后用底栏「加入 N 首」，完成后逐项报告失败，不能全部显示成功。
- 搜索框显示作用域；共享曲库现有接口只有 offset / limit，没有搜索条件。**B** P1 增加有界服务搜索与稳定分页；**F** P0 如仅筛选已加载数据，必须写「筛选当前已加载歌曲」，不冒充全曲库搜索。
- 不一次性拉完整曲库到前端以换取假搜索；结果不足或下一页加载失败有明确提示和局部重试。

### 5.7 共同队列：让「我们一起决定下一首」可见

队列分「正在播放」「接下来」，歌曲行高建议 64px，封面 40px，主标题 14px、歌手 / 点歌人 12px。常显歌曲、点歌人和一个主要参与动作，收藏 / 分享 / 播放 / 移动 / 移除放到更多菜单，不在每行平铺六个按钮。

| 动作 / 状态 | 规则 |
| --- | --- |
| 点歌人 | 「你点的」「小林点的」，保留真实成员身份；未知时写「成员点歌」，不造头像或昵称 |
| 手动排序 | 有权限者使用拖动柄；键盘 / 更多菜单提供上移、下移。P0 可先用现有移动命令，P1 补完整拖放 |
| 按票数排序 | 标题显示「按大家的票数排序」；每行用「支持下一首 · N」或「已支持 · N」，`aria-pressed` 表示本人状态；不能用红心冒充投票 |
| 已开始准备的歌曲 | 标签「即将播放，顺序已锁定」，禁用影响顺序的操作，原因贴近控件；不对用户说「冻结音频前缀」 |
| 投票引起排序 | 服务器确认后调整位置；交互中的行不在指针下突跳；队列出现「排序已更新」提示并维持合理滚动锚点 |
| 无权限 | 显示「房主暂未开放点歌 / 播放控制」；本机音量仍可用。未存在申请权限接口时，不添加无效「申请控制」按钮 |
| 移除 | 确认回执后移除，短提示可提供「重新加入」；不要写「撤销」却创建新实例并丢失票数 / 原位置 |
| 并发冲突 | 保留当前视图，刷新真实队列，说明「队列已被其他成员更新，请再操作」；不直接重放旧顺序 |
| 操作未知 | 当前操作显示「正在确认是否已加入 / 已移动」，查询原 operation；不给可重复发送的按钮。用户仍可阅读队列，受关联锁约束的写操作显示原因 |
| 歌曲已撤销分享 | 使用不可用行态和具体原因，不能通过历史封面 / 收藏继续点播 |

手动拖放、投票和点击播放都按 `instance_id` 操作，不按当前显示行号。键盘移动成功后焦点跟随该条目；减少动态效果时不做重排飞行动画。

### 5.8 聊天、成员与权限：可参与但不喧宾夺主

聊天以侧栏 Tab 为主，保留舞台简洁输入；两处使用现有同一个输入组件和草稿。未读角标只来自真实新消息，查看历史不制造未读。发送中、发送失败、结果未确认分别展示；失败不能默认丢掉文字。

成员页列表展示昵称、房主标签和设备 / 收听状态；点击本人直接打开本机声音设置。房主点他人「⋯」可更改已有权限、禁言、移除。改权限后自然语言总结，例如「可以点歌和聊天，不能切歌」。移除使用一次确认，写明需要重新授权才能回来。

入房申请只在房主界面显示可操作通知：「小林申请加入 · 批准 / 拒绝」，成员 Tab 保留申请列表。默认批准使用「一起点歌」预设，批准前可展开改权限；不要要求房主跨到九个设置分类里寻找待处理申请。

关闭申请提示不会拒绝申请。批准结果未知先查询原请求，不能用重复批准碰运气。成员退出 / 换房 / 权限变化后，打开的菜单和按钮即时按新快照收敛。

### 5.9 声音状态、错误与退出

把状态拆成**房间连接**和**本机声音**两个含义，主界面最多一条状态摘要；只有有问题时升级为横幅。

| 真实条件 | 面向用户的文案 | 行动 |
| --- | --- | --- |
| 房间已连接，输出 ready，未播放 | 已加入 · 等待播放 | 有权限时可播放 |
| 正在播放且输出 ready / enabled / 无错误 | 可收听 · 当前设备名 | 调整本机声音；不宣称跨设备绝对同步 |
| 输出 enabled 但音量为 0 | 本机已静音 | 取消静音 |
| 本机输出关闭 | 本机未开启声音 | 开启本机收听 |
| 正在准备输出 | 正在准备声音 | 说明可先查看队列；持续等待可查看设备 |
| 音频中断 / 输出错误 | 声音暂时中断 | 查看输出设置 / 按实际条件重试 |
| 会话重连 | 连接中断，正在重新连接 | 显示原会话上下文，阻止不确定的写操作 |
| 主机结束 | 房主已结束一起听 | 返回 Hertz / 返回一起听入口 |
| 被移除 | 你已离开这个房间 | 返回入口，不继续自动重连 |

诊断详情保留网络对时、设备漂移、缓冲、欠载、采样率和错误编号；这些数值不占正常舞台。输出 ready 只表示具备收听条件，不能仅据此显示「你已经听到声音」。测试音必须由用户明确点击，不能入房自动播放。

返回 Hertz 保持会话；主应用中的现有浮动播放条继续复用，显示房间 / 歌曲、播放和「返回房间」。收起后仍能找到入口；在工作区内隐藏重复播放条。主应用选歌时明确是「加入当前房间」还是需要先退出回到个人播放，不悄悄替换全房间当前歌曲。

成员离开一次确认；房主结束时明确「所有成员将停止收听」，按钮「结束一起听」。确认不涉及房主转移，因为当前没有该能力。退出后恢复个人队列和位置并保持暂停，给出「继续个人播放」可选动作，不自动出声。关闭设置 / 邀请抽屉 / 浏览器窗口均不等同离开房间。

## 8. 验收：以完成任务为标准

### 8.1 页面交付清单

设计稿 / 实现截图至少覆盖六组，不只交一张漂亮的正常态：

1. 壁纸页：未启用、已显示、未应用修改、显示器缺失、应用失败。

6. 异常恢复：网络断开、队列冲突、权限被收回、房主结束、返回个人播放。

| J-A01 | 从大厅创建正常单网卡房间 | 只需昵称等必要信息，无需操作端口 / 采样率 / 网卡下拉 |
| J-A02 | 多网卡且缺少可靠默认值 | 明确请求选择网络，不偷偷绑定回环或任意首项 |
| J-A03 | 生成邀请后模拟剪贴板失败 | 保留原邀请，提供再次复制；没有生成第二份邀请 |
| J-A04 | 用查找码和邀请分别加入 | 查找码走发现 / 审批，有效邀请走核验 / 加入；不混淆两条路径 |
| J-A05 | 第一次加入房主 / 房主指纹变化 | 在可达的单一面板中完成完整核验，取消后昵称和邀请仍在 |

| J-A07 | 两成员连续点同一首歌 | 一次点击一条；显式再点才再入队；条目署名和实例独立 |
| J-A08 | 点歌后模拟回执未知 | 显示正在确认，查询原 operation，未确认前不重复添加 |
| J-A09 | 双成员同时修改 / 投票 | 以服务结果为准；冲突可恢复；不可移动部分有可理解的原因 |
| J-A10 | 有 / 无权限及中途撤权 | 控件状态立即更新，服务仍拒绝越权；本人音量不误变全房间音量 |

| J-A12 | 返回主应用、收起播放条、回房间 | 音乐和队列不被重建；入口始终可达；无两条重复播控 |

| U-A01 | 1440×900、1280×720、1024×768、390×844、360×740 | 无横向溢出、主要按钮不遮挡，长标题 / 昵称 / 错误可读 |

| U-A03 | 深色、浅色和至少一款自定义主题 | 颜色可读、focus 可见、禁用原因可读，没有写死房间深色背景 |

### 8.3 用户任务指标

以下是拟定验收目标，**当前未测得基线，不把目标写成已经实现的改善比例**。先用原界面记录，再用改版做相同任务；测试机已安装组件，网络和设备可用，分别记录等待服务时间与人的操作时间。

| 任务 | 目标 |
| --- | --- |
| 首次把壁纸放到指定显示器 | 6 名目标用户至少 5 名无需口头指导，60s 内完成，并能说出是否已应用 |
| 歌词锁定后重新调整位置 | 至少 5/6 能在 20s 内找到编辑入口；不会以退出整个组件作为唯一办法 |
| 发起房间并把邀请复制出来 | 至少 5/6 在 45s 内完成；普通网络条件无需解释网卡 / PCM / 端口 |
| 从已在房间现场到添加已共享歌曲 | 入口到单曲添加不超过「点歌 → 选曲 / 搜索 → 添加」三个操作层级 |
| 判断音乐为何没声音 | 至少 5/6 能区分未开本机声音、静音、准备中和连接中断 |
| 判断「返回 Hertz」和「结束房间」 | 至少 5/6 能正确预测行为，无误结束房间 |

首轮以本地任务记录和实际屏幕录制验收，不为了衡量 UI 新增远程行为采集系统。

## 9. 验证方式、迁移与发布控制

- **界面回归：**扩展既有 `scripts/check-room-ui.js`、`scripts/check-room-theme-browser.js`、`scripts/check-room-player-browser.js`，覆盖导航映射、权限预设、焦点恢复、未知回执和窄窗。截图用于视觉核对，不能替代操作断言。
- **服务集成：**复用 `scripts/check-lan-room.py` 等现有真实双成员验收；只在新增共享搜索、管理合同或操作语义时增加针对性测试。前端夹具通过不代表真实邀请 / TLS / 声卡已通过。
- **原生桌面：**按现有桌面验证方式在 Windows 真窗口上检查点击穿透、找回、断屏、全屏策略、预览释放。网页预览截图不能证明真实桌面挂载成功。
- **迁移：**旧壁纸 / 歌词配置原样读取；第一次打开不强制套用新样式。旧房间导航动作映射到新组件；保存的成员身份、邀请语义和个人收藏不变化。
- **移除旧路径：**P0 收拢邀请 / 点歌入口时删除旧页重复 DOM，但保留导航转向；P1 内嵌实时预览落地后删除旧独立预览呈现路径，仍保留一个租约管理者。不得长期同时维护两套可编辑界面。
- **发布边界：**Standard / Full 共用 UI；在线一起听是否开放以该功能自身验收为准。DBX 和不支持原生桌面的环境显示能力边界；小屏验收不宣传手机收听。
- **回滚：**按工作包保留可独立回滚的提交；数据合同有迁移时先验证旧数据读取和失败时不覆盖，不依赖常驻双 UI 作为回滚手段。
