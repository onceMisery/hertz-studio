## 1. 试验边界与顺序

先做 L0，预计最多三个有效工程日的首轮验证；W0 独立给两至三日的首轮窗口。时间盒用完时交付已得证据和未解决问题，不降低通过标准，也不等同承诺在这些天数内完成全部验证。歌词 L0 不依赖 WorkerW；壁纸 W0 可以独立推进。

原型只包含单一原生入口、托盘/退出、对应 surface、状态采样和所需受控输入。L0 先用合成文本与单调位置源验证窗口，W0 先用无音乐星座验证桌面挂载；此时不为原型提前实现完整曲库、模型入口、自启安装器或生产桌面 API。

原型应与正在运行的播放器、DBX 数据和发布二进制隔离，使用专属配置/WebView 数据目录。实验分支或工具入口在转为正式宿主时合并/移除，不保留第二个长期桌面 exe。测试原型能读假数据不证明 L1 真实歌词同步已完成。

## 2. 共同准备与报告口径

登记源码提交及 dirty 状态、编译器/MSRV、crate 和 WebView2 版本、Windows 构建、GPU/驱动、每屏 DPI/刷新率/分辨率、电源和采样工具。至少覆盖一台代表性集显设备及高 DPI 场景；只有一台机器时可以得出该设备的局部结论，支持矩阵缺项继续待验。

同一设备使用“无桌面组件”“组件启用”“功能暂停/隐藏”“全部关闭”四个状态对照。采集整个专属进程树的 CPU、私有提交内存、GPU 指标以及窗口/controller、frame/render 计数；工具不可测的指标记不可用，不用 JS 堆或资源估计替代。

稳定运行、首次启动、窗口恢复与配置切换分段记录。原生录屏/输入结果证明透明和穿透；日志证明状态和时序；截图只证明某一画面。证据按实验 ID 保存，失败也保留。

## 3. L0：透明歌词的最小实验证据

| ID | 操作与观测 | 通过标准 / 不通过时动作 |
| --- | --- | --- |
| L0-1 合成与焦点 | 明暗和动态背景上显示中英/emoji、不同透明度；在编辑器、浏览器与桌面切换前台 | 无黑底/明显残影；非激活置顶且不进 Alt+Tab；失败先定位 WebView/controller 路线，不进入 L1 |
| L0-2 输入与恢复 | 锁定后在文字覆盖区点击/双击/滚动/拖拽其它应用；托盘解锁并定位；模拟托盘重建 | 全窗及 WebView 子窗口均穿透；恢复入口失效时不遗留锁定窗口；不用全局输入钩子补救 |
| L0-3 环境策略 | 同屏/异屏全屏、锁屏、息屏、休眠、用户隐藏叠加；分别解除一个原因 | 隐藏原因互不覆盖；恢复不抢焦点；停绘后十秒没有连续 frame/rAF |
| L0-4 显示器 | 混合 DPI 迁移、断开目标屏、恢复连接、改变任务栏工作区 | 可找回、DIP 尺寸合理、位置钳制；未覆盖的拓扑不列支持 |
| L0-5 所有权与回收 | 启停/锁定循环 50 次；设置关闭；制造 controller 失败；全部功能退出 | 窗口/controller/监听器回到基线，专属进程可退出；无法证明归属时不得批量结束浏览器进程 |
| L0-6 文本更新成本 | 普通整行、真实词时间样式的合成位置、30/15 fps 上限、静态/暂停对照 | 更新只落在当前/次行；无连续布局重建；给出整棵进程树成本，冻结候选资源阈值 |

L0-1/2 不能成立时停止生产接入，记录 WebView2 路线被否定的证据，再评估原生文字 renderer；不能把“取消穿透”当作同一个设计通过。

## 4. W0：桌面层与后台绘制

| ID | 操作与观测 | 通过标准 / 不通过时动作 |
| --- | --- | --- |
| W0-1 挂载与输入 | 一款星座挂图标后；桌面图标点击/拖拽/框选/右键、Alt+Tab | 实际层级正确，输入正常；失败销毁窗口并露出系统桌面，不用前台全屏兜底 |
| W0-2 后台可见性 | 同时记录原生可见性、document.hidden、rAF 与 render；桌面/应用覆盖/策略暂停切换 | 应动时可绘制，应停时十秒无连续 render；不靠全局关闭浏览器节流或伪造音乐状态 |
| W0-3 恢复 | Explorer 重启、断屏重连、锁屏解锁各十次；叠加一次 WebView/GPU 错误 | 恢复预算有界，旧窗口归属失效，无累积实例；到顶后可操作失败，不无限重启 |
| W0-4 时钟与预算 | 无音乐环境运动；模拟 pause/seek/换曲；15/30/60 fps 与可用刷新率组合 | 视觉时间不被歌曲 seek 拉回，暂停恢复无大 dt；主动限帧不误触发降档，记录实际有效 FPS |
| W0-5 回收与环境 | 应用/停止 50 次，切设置预览，运行期间改 Windows 系统壁纸 | 预览租约和 scope 回收；退出露出当前系统壁纸；全部关闭不留专属进程 |

W0 验证的是本机挂载/绘制可行性，不能代替 W1 的真实频谱桥、完整播放共存与八小时长稳。若需要改共享可见性或运动信号，保留原网页默认策略，并在实际改动时运行对应舞台回归。

## 5. 共用宿主的决策实验

由率先落地的原型完成一次即可；另一 surface 接入时补共存反例。

| ID | 必须解决的问题 | 必交证据 |
| --- | --- | --- |
| H0-1 | Rust/WebView2 绑定能否同时满足窗口类型、Rust 1.88 与许可证要求 | 锁定候选版本、最小构建日志、支持/不支持结果；非 Windows 原工作区检查仍可运行 |
| H0-2 | 单实例、用户和会话边界 | 双启动、另一用户/会话冲突、退出再启；只有一个配置写者，原实例不会被静默替换 |
| H0-3 | 专属 WebView environment 归属 | 创建/关闭/controller 失败的进程树证据；决定可用的退出/回收方式 |
| H0-4 | IPC 完成事实与容量 | 在原型内验证配置 revision 冲突、落盘失败、丢回复、慢读/半帧/满载、旧应用完成；给出 wire schema 及大小/连接/排队/期限候选值 |
| H0-5 | 资源阈值 | 在代表设备冻结启用/静态/暂停的 CPU、内存、GPU 发布上限及测量方式；没有数据时结论为待证，不填写臆测数字 |

H0-4 原型只验证共同控制契约，不要求为了实验把全部生产 API 做完。最终字段与上限应回写共享宿主设计，再开始 L1-B/W1-B 的正式协议实现。

| 阶段 | 可进入的下一步 | 必须留待后续的证据 |
