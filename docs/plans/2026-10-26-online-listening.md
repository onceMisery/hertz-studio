# 在线歌曲一起听：缩短首次起播等待

2026-10-26。用户授权优化方案后直接实施，不使用 TDD 或 Aegis 技能。

## 方案

房主从在线搜索、歌单曲目中将歌曲加入共享曲库及共同队列。成员沿用现有点歌权限，接收同一份 PCM，无需平台账号或 Full 版。

常见 MP3、FLAC、Ogg、头部带元数据的 M4A 使用已有渐进下载器，在约 1.5 秒压缩音频的预缓冲后起播（64–384 KiB；码率未知时 256 KiB）。此值是缓存目标，不是网络延迟保证。起播无需等待整首下载。尾部元数据 M4A 保留完整下载要求。下一曲提前准备，共享同曲下载，完整缓存直接命中。

网络解析、预缓冲与格式探测均在房间渲染线程外完成。房间渲染器接收已探测的媒体，不在生产当前节目 PCM 时等待新源网络。单机与房间共用下载器、缓存索引与解码器；房间模式不启动单机播放器。

当前源、候选、后继及仍持有解码器的代际通过缓存租约保护文件。同曲共享下载；最后一个使用者退出后取消未完成下载并释放保护。来源准备总期限 20 秒；本地资源保留 5 秒。完成结果仍由 Host 复核分享 revision、播放实例与 epoch 后提交。

在线来源显式保存在 SharedLibrary，队列编辑只作授权检查，不下载整份歌单。封面和歌词走受限资源通道，不影响音频起播。房主收藏沿用平台身份，接收端保持 LAN 身份。保留旧在线播放门禁、成员权限和 PCM 协议的现有职责。

真实平台速度取决于平台响应、带宽和文件容器。受控慢速服务器须证明下载未完即可起播，不承诺固定毫秒数或扩大跨机声学精度声明。

验证使用独立临时 profile，不读取平台账号。服务库测试 701 通过、5 跳过；前端默认集合 64 步通过，新增覆盖平台引用、待确认队列操作、房主收藏身份、已加载歌单范围、超过 64 首的共享管理。Playwright 检查真实在线行的 1440 / 390 / 360 px 布局和按钮点击，并修复普通在线列表的窄屏操作区。

受控 HTTP 服务只先发送 120 秒 WAV 的前 96 KiB，阻塞全部剩余字节。真实 RenderCore 和房间 Producer 在尾部尚未放行时生成非零 PCM，同曲仅一次 HTTP 请求；一次观测为 201.6083 ms。这是本地受控测试，不是平台首播速度保证。测试同时覆盖活动 `.part`／已完成缓存的清理保护、最后使用者释放、取消超出可用前缀的 seek，以及缓存中定位到 90 秒后实际输出尾段音频。LRU 另验证多租约和相邻歌曲边界。

Standard 的两个真实进程完成 HTTP/TLS 与 WASAPI 静音验收：在线缓存歌曲先播放，再与三个本地采样率歌曲自然衔接；26 秒观测零欠载／重同步，下一首、定位、共享撤销和权限拒绝均通过。机器报告位于 `output/online-listening/standard-native.json`。冷下载提前出声由上述受控网络测试证明；此进程验收使用完整缓存，不依赖外部平台。

Standard 和 Full 均完成独立构建，产物位于 `output/online-listening/bin/`，保留正在运行的旧服务。Full 房主搭配 Standard 接收端重复上述原生验收，26 秒零欠载／重同步，报告位于 `output/online-listening/full-host-standard-guest-native.json`；证明接收端无需 Full 或平台账号。音频核心的 62 项渲染回归全部通过。所有原生验收均为同一 Windows 机器上的两个进程，不作为跨机声学同步证据。
