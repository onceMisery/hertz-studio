# 一起听：个人舞台与在线点歌交互补全

依据：现有 UI 产品化方案及用户后续要求“舞台是各自的”“弹幕聊天”“房主在线点播不方便”。范围仍为电脑局域网体验，当前工作树实现，尚未发布。

## 界面与操作

- 一起听现场增加“打开我的舞台”。完整 Stage3D 接收房间歌曲、封面、歌词及播放时间；场景选择、镜头、主题、效果设置沿用本机舞台偏好。
- 舞台提供明确的返回一起听、点歌／共同队列、发弹幕入口。唯一聊天表单在房间和舞台之间移动，保留草稿、发送与未知回执；弹幕只显示最近的新文字消息，历史不重播。显示开关按浏览器保存，减少动态效果时使用聊天记录。
- 房主点歌抽屉默认“在线歌曲”，另外提供“本机歌曲”“房间已共享”。在线搜索显式选择音源，提交关键词，结果直接“加入共同队列”；添加后继续点歌或查看队列，不自动切歌。不可播、搜索失败、空结果、加载更多、搜索取消和入队待确认均有反馈。
- 原在线歌单与登录页面从抽屉进入，保留既有批量分享能力；成员继续从获授权共享曲库点歌。

## 所有权与修复

HertzRoom 继续拥有房间投影、资源生命周期、聊天及写操作回执。Stage 只接收呈现数据，Stage3D 不复制业务队列；舞台队列入口回到原共同队列。房间播控仍通过权限与同一操作 owner，舞台视觉设置不广播。在线搜索复用 HertzSearch 的全局并发限制、同源串行和取消机制。

实际隔离服务验证发现，分享成功会推进房间控制 revision，原 UI 随后的入队却使用旧 revision，因此直接失败。在线与本机选曲均改用分享成功响应的 revision 再读取队列。冲突仍交由服务拒绝，不自动重放写入。

进入房间作废个人曲目／歌词在途代际；退出后清空舞台呈现并重新读取个人当前歌曲。房间资源继续受分享版本、代际和对象 URL 撤销约束。

## 验证

- `node scripts/check-room-ui.js`：原房间控制、权限、会话隔离与未知操作回归。
- `node scripts/check-room-theme-browser.js`：在线默认入口、共享源切换、主题、窄窗、200% 缩放、原邀请／队列等交互。
- `node scripts/check-room-stage-browser.js`：完整应用与真实隔离房间服务，验证舞台数据、唯一输入框、草稿、实际消息发送和实时弹幕、个人偏好、撤销播控权限、实际在线分享并入队、不自动切歌、不可播歌曲、搜索错误／取消及 390／1280 布局。
- `node scripts/check-stage-queue-browser.js`：个人舞台原队列交互回归。
- `node scripts/check-frontend.js`：前端静态与行为聚合。

新浏览器检查从当前 checkout 加载完整 UI，API 使用已有 `target/ui-productization/debug/hertz-studio.exe` 隔离服务。当前曲目呈现及在线搜索响应使用受控数据；真实 share_online、队列和聊天写入走服务。该检查不访问真实在线平台、不打开声卡，不代表跨机音频或声学同步验收。
