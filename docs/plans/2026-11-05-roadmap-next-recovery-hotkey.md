## 实现边界

- 唯一宿主持有全局偏好，默认空；切换音乐来源不更改组合键。
- 原生桌面中心的“运行设置”支持录入、取消、更换、清除及失败重试；区分保存的组合键和当前真实注册状态。
- 首版支持至少两个 Ctrl / Alt / Shift 修饰键，加字母、数字或 F1–F11 / F13–F24。拒绝 Win、F12 和其它未开放键；不抢占系统保留组合键。
- 使用 `RegisterHotKey` / `WM_HOTKEY`，不安装全局输入钩子。热键只触发已有解锁/定位能力，不控制歌曲，也不绕过会话、息屏或全屏策略。
- 更换时保留旧注册，试注册新键，按 expectedRevision 原子保存，再注销旧键。失败按磁盘实际提交结果补偿，revision 只前进；无法完全恢复时如实显示仍注册的组合键。
- 启动注册失败保留偏好与错误，托盘恢复继续可用；退出注销该宿主全部注册。
- 不扩大 DBX 跨进程管理权限，不修改系统启动项或用户全局热键默认值。

## 所有权

`hotkey.rs` 负责组合键、原生注册和可注入故障的更换事务；`config.rs` 继续作为唯一保存入口。
`app.rs` 串行处理设置、状态与恢复动作，`native.rs` 只转发对应 Windows 消息。
内嵌设置页只采集用户输入和呈现结果，页面按键监听不充当全局快捷键实现。

## 完成证据

1. 实现后验证默认空、旧配置、跨来源保留、非法键、注册冲突、保存失败、注销/补偿失败、启动失败与退出释放。
2. 浏览器验证录入/取消/清除、脏草稿互斥、失败反馈、旧状态兼容、键盘可达与窄窗口布局。
3. 隔离原生宿主验证实际 Windows 注册占用、替换/释放、持久化重启和消息到解锁定位的完整路径。
4. 重建并更新原项目 `output/app/hertz-desktop.exe`，回写路线状态和实际证据边界。

物理键盘、锁屏及多显示器只有实际操作过才计入对应验证；定向发送 Windows 消息不冒充物理组合键输入。
