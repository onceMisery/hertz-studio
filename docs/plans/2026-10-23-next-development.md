### 2.1 关键任务的实施边界

- **PLAY-01：** 页面离场和 DBX 关闭是近期真实变更面，优先验证；真实声卡听测与 null 后端断言分别记录。Full 真实平台账号/权益、NAS 和弱网若缺环境，明确保留待验，不以合成来源补齐。DBX sidecar 重启测试已有证据，仍需真实宿主的启动/关闭旅程。

- **MAINT-01：** 不同时拆播放、在线取流和扫描，不改 `play_commit`、播放代际或离场 grace。若必须新增 owner/锁才能搬动，撤回该拆分方案并重新设计；文件变短本身不是收益指标。
- **MODEL-01：** 不再新增 provider、费用核算或账单任务作为前置；本地模型若可用可独立试验，但不能替代所选云 provider 的 endpoint 验收。没有真实成功证据时继续保持实验性表述。

### Owner / 退役检查

- **现有 owner：** `AppState` 继续持有播放、队列、代际与锁；`vmusic-audio` 负责输出；原歌词模块负责解析和偏移；`CreativeStage` 负责舞台提交态。维护任务只拆文件边界。
- **提议的新 owner：** 尚未实施的 `hertz-desktop` 只管理原生窗口、托盘、来源和桌面配置，歌词/壁纸 controller 分开；该选择仍以桌面草案评审和 L0/W0 证据为准。
- **旧路径与兼容：** OBS 浮层保留原接口，不承接桌面权限；当前无已发布 `hertz-wallpaper.exe` 需要迁移，不创建第二个歌词 exe 或永久转发层。
- **反证：** 关闭播放器页时，桌面只读订阅不能冒充页面观众阻止原暂停；关闭歌词不能关闭仍启用的壁纸；关闭服务不自动拉起播放器；没有音乐时壁纸可独立运行。这些必须分别有原生证据。
- **结论：** 采用交付收敛和小步维护；桌面生产实现仍需原生证据。L0 失败时停止扩展，不自动增加第二套 renderer 或兜底进程。
