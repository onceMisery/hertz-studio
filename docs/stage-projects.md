# 可编辑舞台工程 v1

R6 工程协议复用原 CreativeStage、完整 preset 校验器、参数表与 cue 编辑器。文件保存完整预置、时间线语义版本和可选媒体内容身份，不包含音频、路径、账号、封面 URL 或任意资源地址。分享码和视频文件仍是独立产物。

## 协议与确认

工程信封为 `projectVersion=1`、`timelineVersion=1`、当前 `schemaVersion/schemaHash`、完整 `preset` 和 `media`。`media` 为 null 或 `{kind,sha256,byteLength}`；哈希针对完整文件字节，标签改变也会改变身份。本地文件仍返回 `kind="local-file-sha256-v1"`，在线完整缓存与远程文件返回 `kind="file-sha256-v1"`。两种已知版本都表示完整文件 SHA-256；哈希和长度相同时可跨来源绑定，旧本地工程无需重写。未知 kind 拒绝，转码、音质不同或仅曲名相同不算相同内容。完整预置中的 `stage.seed` 随文件保存，不承诺音频分析、随机导演或跨 GPU 像素一致。

导出读取 committed preset，不导出临时预览或未确认候选。自定义图片/视频背景按原分享策略转换为主题背景并明确提示，素材需另选。检查导入不应用、不调用模型、不加载文件；显式应用后仍保留原参数/编排编辑入口。未知版本、契约不一致、过大/过深数据、危险键和无效完整预置拒绝。上限 256 KiB、12 层、64 cues、32 bindings。

应用工程不会点播、seek 或自动绑定当前曲目。工程的 cue 轨在确认媒体前停用，静态预置和人工参数编辑仍可用。确认当前曲目时，通过官方 HTTP/RPC 入口仅按曲库或在线虚拟 ID 核对完整内容；内容不匹配则拒绝绑定。未绑定工程可显式选当前曲目建立身份。确认后只在本次播放曲目身份周期内生效；换曲、切空或页面刷新后须重新确认，即使再切回同名或原曲也不自动恢复绑定。

媒体确认是此刻完整文件或完整远程响应的内容校验，不持续重读正在播放的文件，不证明解码器已打开的字节与后来修改的文件或远程响应一致。外部修改文件或远程资源后应重新载入并确认。可保存未绑定工程。

## 时间线 v1

歌曲位置来自 Stage 的唯一毫秒时钟。沿用 preset.cues 的 `at`（歌曲绝对秒）、`len`（毫秒）和 `ease`，按 at 升序、同一 at 按文件顺序处理。每个参数独立：后 cue 在其开始时采样前 cue 的插值值，从该值过渡到新目标；同一时刻后出现的目标覆盖先出现的目标。完成后保持目标，未开始返回基础值。初始插值值来自 preset 基础参数，不从实时频谱或上次帧取值。

每帧由当前位置重算，不保存「已触发」标记。因此向前/向后 seek、跳过整个 cue、暂停 seek 和反复访问同一位置得到相同绝对轨结果；暂停冻结歌曲时钟。换曲后清除本次媒体确认，并停止旧曲 cue。参数顺序为基础值/音频绑定→绝对时间 cue→人工触发/导演补间，最终仍受既有参数范围和相机层约束；音频绑定与导演不是可复现绝对轨。

`every` 节拍 cue 保留为既有实时规则，不伪造缺失的拍点/基频数据。同一条工程 cue 不允许同时声明 at/every。工程明确保留节拍规则的非确定性；它不属于 seek 可重算的绝对轨。最多 64 条 cue、32 条音频绑定、原有最多 24 个活动补间、原参数及帧门预算不扩容。不新增模型时序输出或每帧模型调用。旧 preset/分享 v1 保持原音频叠加起始值；仅显式应用工程后使用此时间线版本，不静默改写旧格式语义。

## 指纹读取边界

官方 `POST /v1/stage/project-media` 接收 `{track_id,allow_remote_read?:boolean}`，远程读取默认关闭，与 DBX RPC 共用同一实现。它不接受文件路径、URL 或模型参数，不加入受限 MCP registry。全部来源共享全进程单槽、不排队，完整内容最多 2 GiB、64 KiB 读取缓冲。工作循环检查含数据库等待的 10 秒期限，调用含数据库等待最多 12 秒；超时/取消后后台若仍在系统 I/O/钥匙串调用中，执行槽保持到实际退出。服务端不缓存或持久化指纹，客户端在已应用工程的自动保存和工程文件中保存内容身份。

- 本地曲库：仅普通文件，读取前后大小/修改时间变化则失败。
- 在线曲目：仅核对当前播放流程实际选中的完整缓存。缓存命中使用原确切路径；渐进下载成功 rename 后才发布实际终文件路径，保留降档/实测改名，不按最新音质偏好重新选文件。不读 `.part`，未完成、已清理、无法证明对应当前播放的缓存拒绝；不为核对而重新取流或下载。渐进 rename 失败后复用旧终文件时，不假定它等于解码线程已读的字节，应重新载入完整缓存后确认。
- 远程曲库（WebDAV/HTTP）：先在工坊勾选「允许读取远程完整音频」，再确认或保存含媒体身份的工程。每次操作只发一条完整 GET、不落盘，可能消耗完整文件流量；不自动 HEAD、Range、续传、重试、重定向、解压或代理。仅接受 HTTP 200、无 Content-Range、无非 identity 编码的完整响应，检查声明长度和读取中的实际长度。来源 URL 只能来自原曲库，凭据从原钥匙串取，同 origin、完整路径段和最长范围匹配，拒绝串前缀兄弟目录、encoded 分隔符及二次解码歧义。远程许可不写入工程或保存 UI 状态；刷新或重建该表单后重新勾选。

远程指纹证明本次响应的完整字节，不是服务器版本锁、许可或实时播放内容证明；不同时间的响应可能不同。重定向服务器须改登记为最终地址。原生 DBX、真实 NAS/账号/弱网及跨 OS 仍需独立验收。受控复现：构建隔离二进制并设置 `HERTZ_BIN`、`PLAYWRIGHT_MODULE` 后执行 `node scripts/check-stage-media-browser.js`；与既有 `check-stage-project-browser.js` 分开记录，默认前端检查不联网。

## 手动分段与规则编排

在工坊→高级编排→编排中展开「按分段生成编排」，填写开始秒数、规则和过渡毫秒。提供的 0/30/60/90 秒为手动示例，不是歌曲分析结果。支持 1–32 个分段，首段从 0 秒开始，后续时间须严格递增且不超过 86400 秒；过渡 16–600000 毫秒，不能越过下一分段。末段到达目标后保持，可添加「原始参数」段回到生成时的基础值。

平静、叙述、增强直接复用本版本 CreativeStage 自动导演的八个光感/运动参数规则；原始参数读取当前 committed preset 的对应基础值。它们是本地规则，尚未作为经人工视觉验收的创作模板发布。生成保持场景、镜头基础位置、其它参数与音频绑定，关闭自动导演，整条 cue 轨替换为生成的歌曲时间 cue。自定义背景继续遵守工程素材剥离规则并显示提示。原有实时绑定和相机层依然可能影响最终画面。

「检查分段」是纯准备，显示生成条数、将替换的旧 cue 数量、保留的绑定数及素材提示；点击「替换当前编排」才通过原工程入口提交。参数、预置或分段改动会作废已检查方案。应用后媒体确认失效，不自动播放/seek/读取音频；可通过「媒体确认与工程保存」转到导出页确认文件身份。生成后下方 cue 是唯一保存与执行的数据，分段输入只是生成表单，不单独保存为第二份时间线；重开工程后编辑 cue 的时刻、目标和缓动即可，不会由旧分段表重新覆盖。

例如为一首本地曲目设置平静→叙述→增强→原始参数，检查并应用，确认媒体后保存工程。重开工程、再次确认媒体，再在 cue 编辑器修改分段边界；分享码可携带同一组数值 cue 和 schema/timeline 版本标记，但会剥离媒体指纹。载入分享码后工程 cue 保持停用，用户须在“可编辑工程”中确认当前媒体后才执行；普通预置分享码继续保留原有行为。视频导出使用当前呈现，不改变工程内容。整个过程不调用模型，不识别歌词段落，也不生成基频轨迹。

## 使用与验证

工坊→高级编排→导出→可编辑工程：点击「下载可编辑工程」保存 `.hertz-stage.json`。默认包含当前本地曲目指纹，没有本地媒体时可取消勾选，保存未绑定工程。导出不改变当前舞台或自动确认媒体。

重开时选择工程文件，点击「检查工程」查看场景、cue 数量、媒体身份与素材提示，再点击「应用已检查工程」。选中内容相同的本地文件后点击「确认绑定当前曲目」，不要求同一路径或曲库 ID。参数与编排页可继续修改基础值、cue 时间、目标和缓动曲线；完成后重新导出文件。自动保存保留工程元数据，但不会在刷新后恢复媒体确认。旧契约不会自动迁移，版本不兼容需保留原文件并用兼容版本打开。

视频入口继续使用 [舞台视频导出](./video-export.md)，录制的是当前呈现，独立于可编辑工程文件。

编排页还可显式查看[实验性基频候选轨迹](./pitch-track.md)，复用本地完整内容身份与 Stage 时钟；查看结果不写工程或生成 cue。

从[创作模板候选](./stage-templates.md)开始时，先预览并确认完整替换，再编辑参数或生成分段；模板应用会清除原工程上下文，保留旧作品须事先另存。

```powershell
node scripts/check-stage-project.js
node scripts/check-stage-arrangement.js
node scripts/check-frontend.js
$env:VMUSIC_BACKEND='null'
cargo test -p hertz-studio --lib stage_project:: -- --test-threads=1
# 浏览器检查需要已构建服务与 Playwright，可指定 HERTZ_BIN/PLAYWRIGHT_MODULE。
node scripts/check-stage-project-browser.js
```

确定性检查加载真实场景、参数与 preset owner，覆盖严格信封、重复键、纯导入、媒体匹配/迟到响应、换曲/刷新失效、顺序/重叠 cue 和可逆 seek；分段检查覆盖规则同源、无副作用检查、输入上限、过期方案拒绝、原参数复原及工程/分享往返。隔离浏览器使用真实文件 SHA-256、导出/重开/检查/应用/绑定、分段生成、cue 编辑与暂停 seek，并经现有原生导出器录制、下载、解码视频；没有模型调用。原生 DBX、真实媒体/GPU/弱机与视觉模板人工验收仍列入发布矩阵，不能把本机浏览器检查替代这些证据。
