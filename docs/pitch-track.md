# 实验性基频候选轨迹

本增量落实技术路线 R6 的服务端基频分析，复用现有后台预算与 Stage 时钟。基频候选不等于多声部音乐的主唱旋律或乐谱；算法质量须单独评测，尚不作为已验收的创作模板发布。

实现范围：

1. 在 `vmusic-beats::pitch` 实现有界文件解码、抗混叠降采样与基于归一化自相关的基频估计，低置信度输出空点。
2. 在 `stage_pitch` 通过曲库 ID 解析本地文件，与节拍分析共用两个执行槽，槽满立即拒绝。完整内容 SHA-256、算法名与版本作为缓存键，内存最多八轨，不写新磁盘缓存。
3. 官方 HTTP/RPC 共用请求实现，不注册 MCP 工具。工坊仅显式分析，不自动读音频，不应用舞台、生成 cue 或修改工程；切歌/退出/切页后迟到结果不进入界面。
4. 实现后用固定频率、谐波、噪声、静音、频率跳变、多采样率与取消/期限信号验证；服务检查覆盖内容变更、预算、缓存和双门面；浏览器检查真实服务及窄屏布局。

源文件最多 2 GiB，分析最多前 720 秒，不推演尾部；分析率 8 kHz，1024 样本窗、40 毫秒步长，候选范围 55–1200 Hz。先用六阶低通处理再降采样，窗口去直流后用 FFT 自相关及能量归一化估计周期，保留低置信度的空点。三十秒服务期限包含数据库、完整哈希、解码与分析；请求 future 被丢弃会发出协作取消信号，但系统文件 I/O 未退出时执行槽仍由后台 owner 持有。浏览器停止等待不保证 HTTP 服务立即取消；DBX invoke 没有中止能力，实际工作继续受服务期限与预算约束。无法判定、过短或静音不伪造频率。

缓存内容是完整文件身份与该算法版本下的可重建结果，不包含路径或曲名，不进入分享码/工程文件。缓存命中仍重新计算完整文件身份；读取与分析前后检查文件大小/修改时间，变化则拒绝。此检查不承诺检测所有保留大小与时间戳的外部并发改写；媒体修改后应重新载入再分析。

合成信号评测证明频率、时间、静音和边界行为，不代替真实歌曲标注、听测、主旋律分离或硬件性能验收。真实声卡、GPU、弱机、原生 DBX 和候选发行版仍由发布矩阵分别验收。

## 使用与接口

选中本地曲库曲目并完成载入，在工坊→高级编排→编排展开「查看基频候选轨迹（实验）」，点击「分析当前本地曲目」。显示前 12 分钟的对数频率图和当前歌曲时间读数；暂停、前后 seek 由原 Stage 时钟决定。空白是无可靠候选，分析尾部之外不延伸。图形最多 1200 个采样顶点，所有空点仍切断连线；不另建帧循环或计时器。

关闭、切页、换曲或同曲新的媒体身份周期会作废未完成的观察结果；再次打开须显式分析。结果只在当前查看和服务内存缓存中，不写工程、分享码、cue、预置或收藏，不自动读取音频。外部修改文件后先重新载入再分析；本地文件身份不证明先前解码器已经打开的字节与修改后的文件一致。

官方 `POST /v1/stage/pitch` 与同名 DBX RPC 仅接收 `{ "track_id": "曲库 ID" }`，要求官方管理认证，拒绝额外字段；受限 MCP 没有此工具。响应为 `{media,cached,map}`，`media` 使用[工程指纹](./stage-projects.md)协议，`map` 包含 `version=1`、`algorithm=nsdf-lowpass-v1`、`analyzedMs`、`truncated` 和 `{t,hz,confidence}` 点列。`t` 是歌曲毫秒，首点 64、步长 40，只有完整窗口输出点；`hz=null` 为无可靠周期。恰好 720 秒结束不标截断，多一个分析采样才标记 `truncated=true`，不复制尾点。

稳定错误包括 `pitch_busy`（429）、`pitch_timeout`/`pitch_cancelled`（408）、`pitch_local_only`/`pitch_unsupported`/`pitch_decode_failed`/`pitch_media_unavailable`（422）、`pitch_media_changed`（409）、`pitch_media_size`（413）。不存在曲目与非法入参沿用通用错误。错误保留原 request_id，不回显文件路径或曲名。客户端给此接口 35 秒传输等待，POST 不自动重试；停止等待与后端实际退出是不同事实。

合成评测方式与边界见[评测说明](../evals/pitch/v1/README.md)。
