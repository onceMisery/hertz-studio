# 搜索共享额度的长时受控压力与测试进程内存 v2

2026-10-18，Windows Standard / Full 各运行三轮两分钟的混合负载，前置和每轮结束各空闲十秒。实际 HTTP 单源、RPC 单源、HTTP 旧聚合和 RPC 旧聚合共用原 AppState / SearchGate。只在测试编译内替换已登记 provider 的网络读取，执行原 JSON 读取器；没有平台协议、真实账号、模型、声卡、浏览器或原生 DBX 的验收结论。方法与复现命令见[搜索性能说明](../../../docs/search-performance.md)。

本机 Windows `10.0.26200`、Intel Core i7-13620H、16 逻辑核、约 32 GiB 内存，rustc 1.98.1、Node 22.14.0。HEAD 为 `401a90376c0fa8391b5d60234103eeb381ef2c2c` 加未提交改动；test profile、四个 runtime worker、保留 debug assertions，关闭增量及 dev/test 调试信息。构建、冻结测试产物、临时库与原始报告均在 D 盘，未设置 affinity。这不是 release 性能或候选包验收；[v1 历史记录](../pressure-v1/README.md)保持原环境和结果。

等待超时的调用没有到达上游；执行槽和十六等待席满载后取消，实际槽位与连接均恢复。头/体停顿分别通过原六秒期限。每波再次核对本地执行数、上游已读请求、请求身份与聚合来源数量，三轮结束后另发成功 HTTP 单源查询。上游 handler 观察 EOF 可能晚于本地 future 结束，峰值五不等于五个本地执行；每波两种计数均归零，已读请求与回复/断开对账一致。

负载为固定三十二客户端的超额突发，RPC 直接到达门面，HTTP 还经过回环传输。**不证明四入口公平性或有效搜索吞吐。** Full 的混合阶段 HTTP 单源为 6295 次 busy、1 次取消，没有成功回复；Standard 同入口为 6088 次 busy、7 次取消、3 次上游拒绝、6 次成功。边界矩阵和最后恢复查询覆盖实际 HTTP 单源成功路径，不能把它们冒充持续过载中的成功率。聚合外层 200 也可能全部来源失败。逐入口状态分布及包含 busy/取消的 P50/P95 保留在摘要，不套用本地曲库或用户体验延迟目标，不冻结原 4/16/2 秒/6 秒候选额度。

内存观察对象是**同一个测试 PID 中的服务、Rust 负载驱动和回环上游**。Node 运行器和 PowerShell 采样器不计入；不是独立生产服务 RSS。每 500 ms 读取 Windows 工作集、私有提交量、虚拟内存、句柄及线程；工作集不等于 PSS，私有提交量不等于驻留内存。阶段按 stdout 接收时间关联，保留 Rust 单调时间与接收时间以复核偏差。紧凑记录在基线前预分配，最后空闲后才转为 JSON；序列化和关闭的 `complete` 阶段单列，确有明显额外分配，不并入空闲比较。
